## [Unreleased]

### Added
- Processes on Windows (milestone 267, PRP-296): `Proc`'s `run`, `run_with`, `call`, `run_bytes` and `run_bytes_with` work on Windows with never a shell. The program found is named to `CreateProcessW` by its path, so Windows searches nothing, and each argument is quoted by the Microsoft C runtime's rules, so it arrives as given (quotes, backslashes, `&|<>^%` and non-ASCII text included). A bare name is looked up on `PATH` only, as given or as `.exe` then `.com`, never in the current folder or this program's, where Windows' own search would look first. Batch files (`.bat`, `.cmd`) are refused, since they run through cmd.exe, a shell; so are a command holding `"` and a command line longer than Windows allows. The child inherits exactly its stdin, stdout and stderr, named in a handle list; stdout and stderr are read on threads of their own, so a megabyte each way at once can't deadlock; a captured run starts with no window. Exit codes are Windows' own: a crash's exception code comes out negative. `tests/windows/process.la` runs itself as its child, so every argument is checked as a round trip.
- The program suite on Windows (milestone 265, PRP-295): CI's Windows job runs every run case in `tests/programs/`, built for Windows on Linux, as the Mac job does: stdout, the exit code and any expected stderr compared byte for byte; `tests/windows/known.txt` lists the expected differences, each with why (processes not yet supported, paths starting with a drive, no `/dev/fd`, a crash in C not being exit 139, no local time past the year 3000), and the job fails on any other failure or on a listed case that passes. The Mac's builder and runner became one for every system: `tests/platform_suite.rs` (`LUGHA_SUITE=<folder> LUGHA_SUITE_TARGET=<triple>`, replacing `LUGHA_MACOS_SUITE`) and `tests/suite.sh <folder> <known list>`, which limits each case with `timeout` where it exists and starts it through `$LUGHA_SUITE_RUNNER` when set (`wine`, to run the Windows suite on Linux). A build refused with E0337 is skipped with why, and zig's `.pdb` files are left out of the suite.
- Sockets on Windows (milestone 262, PRP-294): `std.net` works on Windows as on Linux and macOS: TCP listen, connect, accept, read and write, UDP with multicast and its options, `interfaces()` and name lookups, with timeouts, cancelled scopes and `close` from another task. Every socket is overlapped and tied to the runtime's I/O completion port: an operation is started and its task parked until the completion arrives; one cut short (a timeout, a cancellation, a close) is cancelled with `CancelIoEx` and its task still waits for the completion, so Windows never writes into a buffer that has moved on, and a read that finished first keeps its bytes. Listeners use `SO_EXCLUSIVEADDRUSE` (Windows' `SO_REUSEADDR` would let another program take the port); UDP sockets ignore an earlier send's "port unreachable", as Linux does; a datagram longer than `max` is refused with its real length. Interfaces are named as Windows' `if_nametoindex` takes them (`loopback_0`, `ethernet_32768`), and a link-local address carries that name after `%`. Errors and lookup failures read in Linux's words (`Connection refused`, `Name or service not known`). Programs link `iphlpapi`. A Windows TLS client still trusts only `ca_pem` until Windows' certificate store is read.
- Folders on Windows (milestone 260, PRP-293): every `Dir` works on Windows and is confined as on Linux and macOS, by walking each path one name at a time as Go's `os.Root` does: each name opened alone relative to the folder handle reached, never following a reparse point; relative symbolic links walked, absolute ones and junctions leading outside; `..` never asked of the system. `/` and `\` both separate names; a drive, a share, a data stream (`:`) or `?` leads outside, and names Windows reserves (`NUL`, `COM¹`, `name.`) are refused. Removing and renaming use Windows 10's POSIX semantics and act on handles, never full paths. `set_mode` sets or clears read-only (from the owner's write bit), and `sync` of a folder is `Ok`. Errors read as Linux's.
- Hello world on Windows (milestone 259, PRP-292): `--target=x86_64-pc-windows-gnu` builds a Windows executable (`<stem>.exe` without `-o`) on Linux through zig's MinGW, which runs on Windows 10 or newer with nothing installed. The console, arguments, environment, clock, randomness, tasks on every CPU, channels, timers and panics work as on Linux: task stacks grow through a guard page (the task switch carries the thread's stack bounds), panics unwind through Windows' own unwind tables, and a C stack overflow is reported as `panic: stack overflow`. Text to a console goes as UTF-16; to a file or pipe it is the program's bytes, `\n` included. Folders, sockets and processes return `Err("… aren't supported on Windows yet")`, and process lockdown isn't applied (`LUGHA_LOCKDOWN=report` says so). An `extern struct` passed to C by value is the new E0337 on Windows, whose rules for it aren't lowered yet. `tests/windows.rs` runs the cases under Wine; CI runs them on Windows. The runtime's direct POSIX calls (stacks, faults, signals, stream locks, `getline`, local time) moved behind the OS layer, unchanged on Linux and macOS.
- A Mac's own certificate checks (milestone 258, PRP-291): on macOS a `std.tls` or `std.http` client asks the system's verifier (`SecTrustEvaluateWithError`; the Security framework is loaded while the program runs, since a Mac build is made elsewhere) whether to trust a server, instead of reading `/etc/ssl/cert.pem`. A Mac program now trusts what Safari and curl trust there: roots a user or a company added to the keychain are accepted, and authorities Apple distrusts are refused at once, not after the file catches up. `ca_pem` adds to the system's roots, as on Linux; `SSL_CERT_FILE` and `SSL_CERT_DIR` aren't read on a Mac; refusals read as on Linux (`certificate verify failed: hostname mismatch`, …); a Mac whose verifier can't be loaded trusts nothing. The verifier may go to the network, so it runs on a helper thread: the handshake pauses between OpenSSL calls and resumes with its answer.
- TLS and crypto for another platform (milestone 257, PRP-290): a build with `--target` of a program loading `std.tls`, `std.http` or `std.crypto` links the OpenSSL built for that target which `LUGHA_OPENSSL_<TARGET>` names (the triple in capitals, `-` as `_`; a folder holding `include/openssl/ssl.h`, `lib/libssl.a` and `lib/libcrypto.a`), statically and by path, so the program runs with nothing installed. Without it the build is E0334 as before, whose help now names the variable; a folder that isn't one is the new E0336. On macOS a TLS client also trusts `/etc/ssl/cert.pem`, the roots macOS ships for OpenSSL-based tools. `tests/macos/openssl.sh <target> <folder>` builds OpenSSL 3.5 LTS (pinned, SHA-256 checked) with zig; CI builds it for the Mac, so the suite's TLS, HTTP and crypto cases run there, and a Mac case verifies `github.com` against those roots.
- The program suite on a Mac (milestone 256, PRP-289): CI builds every run case in `tests/programs/` for `aarch64-apple-darwin` on Linux (`tests/macos_suite.rs`, an ignored test run with `LUGHA_MACOS_SUITE=<folder>`, several builds at a time) and its Mac runs them with `tests/macos/suite.sh`, POSIX `sh` and perl, as `tests/programs.rs` runs them: one worker, the case's arguments, stdin and environment, from the repository's root or a fresh folder, 30 seconds each, stdout, the exit code and any expected stderr compared byte for byte (a build's own warnings taken off the front). A build a Mac refuses (E0334, E0335) is listed as skipped; `tests/macos/known.txt` names cases expected to fail there, each with why, and the job fails on any other failure or on a known one that passes. Built for Linux, the same script passes every case.
- Process lockdown on macOS (milestone 255, PRP-288): Seatbelt limits the whole process, C code and started programs included, for the two kinds it refuses reliably. Without `Net`, no socket connects, binds or sends to an address, an internet socket's or a named UNIX socket's; making a socket isn't refused (on a real Mac, `sandbox-exec` showed Seatbelt's `system-socket` rules aren't enforced, even a plain deny), but it reaches nothing; an unnamed pair still works, as on Linux. 0.18.11 also tried to refuse making sockets, which did nothing, and said so; the rule is gone and the docs say what holds. Without `Proc`, no fork, vfork, posix_spawn or exec. Files aren't limited by the kernel on macOS: a profile for them would have to allow name lookups, certificates, time zones and lazily loaded libraries, which change between versions. The profile allows by default and only adds these denies; with both kinds held nothing is applied. If the system refuses it the program goes on and `LUGHA_LOCKDOWN=report` says why; the report always says `files not limited`. `sandbox_init` is declared by the runtime (the SDK leaves it out) and stays in `os/darwin/` (`src/link/mod.rs`). CI's Mac runs `lockdown_bare` (no fork without `Proc`), `lockdown_held` and `lockdown_child` (a started `perl` refused a connect, a bind and a datagram sent to an address, and a named UNIX socket's connect, passing a byte through a pair) and checks both report lines.
- Folders on macOS (milestone 254, PRP-287): every `Dir` works on macOS, confined as on Linux. macOS has no `openat2` (and its own "beneath" flag is missing or silently ignored before 15.4), so the runtime walks each path itself, as Go's `os.Root` and cap-std do: each name opened alone with `O_NOFOLLOW` from a folder already reached, each link read and its target walked the same way, `..` only undoing a name gone down through, at most 40 links and 4096 bytes per lookup. A folder needs search permission only (`O_SEARCH`). The same results and messages as Linux, `..`, absolute paths and links leading out included; one difference: a `set_mode` whose file is swapped for a link at the last moment changes the link's own mode. The folder code moved, unchanged, into `os/posix/dir.c` and `dir_names.c`; each system's lookup is `os/<system>/dir_resolve.c`, so Linux runs exactly the calls it did. CI's Mac runs `folders`, `confined` (Linux's case and output), `dir_race` (a folder swapped for an outside link while it is read: never leaks) and `search_only`, each in a folder of its own; the macOS runtime must compile with no warning under `-Wall`.
- Hello world on macOS (milestone 251, PRP-285): `lughac build --target=aarch64-apple-darwin` on Linux makes a Mach-O executable for Apple Silicon (macOS 14.4 or newer), through zig. The runtime joins `os/darwin/` for it: the OS layer on kqueue and `os_sync_wait_on_address`, the running thread's worker through a pthread key (macOS's thread-locals sit at no fixed offset from the thread pointer, so the worker lookup moved into the OS layer for both systems), and the task switch in Mach-O form. For now every folder operation is `Err("folders aren't supported on macOS yet")` and process lockdown isn't applied, which `LUGHA_LOCKDOWN=report` says; `run` and `test` refuse a Mac target. CI builds `tests/macos/` on Linux and runs it on a macOS runner. Shared fixes found on the way: `memrchr` (a GNU extension) replaced, and `sigtimedwait` (which macOS lacks) in `os/posix/process.c` is `sigwait`.
- Running and testing for another CPU (milestone 248, PRP-282): `lughac run` and `lughac test` take `--target`; an executable for this machine's CPU runs directly (static musl ones included), one for another CPU under `qemu-aarch64` or `qemu-x86_64` from `PATH`, with `QEMU_LD_PREFIX` pointed at `/usr/<arch>-linux-gnu` for glibc builds. A missing qemu, or no C library for it, is exit 2 before building. Process lockdown doesn't apply under qemu. CI installs zig 0.17.1 (its SHA-256 checked) and sets `LUGHA_CROSS_TESTS=required`, so the ARM64 and musl tests run there instead of skipping; `gcc-aarch64-linux-gnu` is no longer needed.
- Building for another platform (milestone 247, PRP-281): `lughac build --target=…` for any machine but the one lughac runs on compiles the runtime and links with `zig cc` (0.17.0 or newer, found on `PATH`), which carries a C library and a linker for every platform; builds for this machine still use `cc`, and `$LUGHA_CC` overrides both. New targets `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` give static executables that run on any Linux (Alpine, old distros, `FROM scratch` images). zig links its unwinder (`-lunwind`) so panics unwind, and keeps its cache in lughac's (`<cache root>/zig`). A foreign build of a program using `std.tls`, `std.http` or `std.crypto` is E0334, and a `[link]` `pkg-config` line E0335: both would link this machine's libraries into another platform's program. Missing or older zig is exit 2, naming the target and `$LUGHA_CC` (`tests/musl.rs`).
- Process output as bytes (milestone 245, PRP-278): `proc.run_bytes(cmd, args)` and `proc.run_bytes_with(cmd, args, input: u8[])` give `ProcessBytes`, stdout and stderr as `u8[]`, never checked as UTF-8, so a program writing binary or non-UTF-8 output no longer loses it; `run`'s UTF-8 error now names them. **Breaking:** a hand-written `Proc` must add the two methods. Captured output stays unlimited, now stated in the spec and docs.
- JSON diagnostics everywhere (milestone 244, PRP-277): every JSON diagnostic carries `"rendered"`, its text as the human format prints it, so a tool can show lughac's own words; `lughac fmt` and `lughac test` take `--diagnostics=json` like `build`, `run` and `check`, for their syntax and compile errors on stderr (`test --json` still means the results on stdout).
- Channel and handle cycles are freed (milestone 243, PRP-275): an actor lets go of its state when it ends, so actors holding each other's handles in a ring are freed once their scope stops them; a `Receiver` is now the channel's counted receiving end, and once the last one goes the channel lets go of what it buffers, so a value holding the channel's own sender no longer keeps it alive. On such a channel `send` drops its value (a sender waiting for room goes on instead of deadlocking), a `select` send arm is ready, and `try_send` gives `.Closed(v)`. A channel holding its own receiver is still never freed.
- An actor's name is its handle (milestone 242, PRP-274): inside an actor's body its name, as a type, now means its handle, as everywhere else, and `Self` its state, so an actor can hold, take and send handles of its own type (`out: Option<Sender<Holder>>`), which couldn't be written before. The parser records where `Self` was written (`Program::self_types`) and the checker reads it; E0403's help names `Self` and the handle when they are mixed up. **Breaking:** code that wrote the actor's name for its state writes `Self` (`fun new(start: i64): Self = Counter { count: start };`).
- Weak references (milestone 241, PRP-273): `Weak<T>` refers to a `Ref<T>`'s box without keeping it alive, for caches, observer lists and links back to a parent; `Weak.new(r)` makes one and `w.get()` gives `Option<Ref<T>>`, `.None` once the box is freed. A `Weak` points to its box's weak cell, which the box empties when it is freed (by its count or by the cycle collector); boxes carry the cell's word only in programs that use `Weak`. `Weak` follows `Ref`'s rules (no `==`, not `Sendable`, never a constant) and prints as `Weak(…)`. `lughac test` notes the cycles a test left for the collector, with where their boxes were made (`--json`: a `cycles` field); the note is never a failure. MEM-08's lint is dropped. **Breaking:** `Weak` is a reserved name, like `Ref`.
- A cycle collector for `Ref` boxes (milestone 240, PRP-272): a `Ref` whose contents can reach another `Ref`, a function value or an interface value is made as a cell; a cell let go of but still held joins its task's suspects, and at the task's next scheduling point past a threshold (256, adapting between 64 and 100 000 by how much each run frees) trial deletion frees what only the suspects hold, walking each object's own visit and stopping at shared objects, so no lock is taken. A task's remaining suspects are looked at when it ends. `LUGHA_RC_REPORT=1` adds `N cycles freed (M boxes)`; `=2` lists where the collected boxes were made. Programs that may make cells count down to scheduling points even without tasks; others run the same code as before. `types/shared_boxes/linked.la` no longer leaks. Channel and handle cycles stay (CLAUDE.md's known issue).
- `ReadDir` (milestone 237, PRP-269): a folder that can only be read is its own capability interface. `dir.read_only()` gives a `ReadDir`, with only the reading methods (`read_file`, `read_bytes`, `list`, `exists`, `is_dir`, `is_file`, `size`, `open`, `path`, and `dir`, which stays read-only), so a function taking one can't write, by its type; a writing method on one is E0415 with help to take a `Dir`. `Dir` doesn't extend it: narrowing is written. **Breaking:** `read_only()` returned a `Dir` whose writes were `Err("the folder is read-only")`; code passing it where a `Dir` is expected no longer compiles, and a `Dir` fake's `read_only()` returns a `ReadDir`. The skill teaches it.
- W0108 (milestone 236, PRP-268), from five readers' notes on §10: a struct or enum that derives `Eq` (`with Eq`, `with Key`) but writes `Ord` by hand is warned of at its name, since its `==` compares every field while `cmp` may compare fewer, so two values can be neither equal nor ordered. The help suggests an `impl Eq` comparing what `cmp` compares, or `with Ord`. Deriving both or writing both isn't warned of. The spec's Ordering example writes its `impl Eq`, and the skill's structs page says so.
- The skill's tasks and examples (milestone 235, PRP-267), completing its layout: `tasks/` how-tos for a command-line tool, a TCP server, an HTTP service, wrapping a C library (real C linked through `lugha.toml`) and testing, each with steps whose code (`lugha part`) must appear word for word in the page's whole program; and `examples/` programs (word-count, parallel-sum, kv-server, notes-api, config), each ending with an `// Output:` block the tests compare against a run with no input. `tests/skill_tasks.rs` checks both; `lughac skill word-count` prints a program. Every line of code in the skill is now compiled by the tests.
- The skill's library pages, second batch (milestone 234, PRP-266): `library/net`, `library/http`, `library/tls-and-crypto`, `library/json-and-toml` and `library/env-and-processes`, each naming every public item of `std.http`, `std.tls`, `std.crypto`, `std.json` and `std.toml` (their internal parts included) and every method of the prelude's `Net`, `Listener`, `Conn`, `Udp`, `OnlyNet`, `Env` and `Proc`. The network and HTTP examples run over loopback; none reaches the internet. The library checks moved to `tests/skill_library.rs`, and a prelude block that marks some methods `public` is checked for those only.
- The skill's library pages, first batch (milestone 233, PRP-265): `library/text`, `library/collections`, `library/console-and-files` and `library/numbers-time-random`, reference tables of every method with what it gives, panics or errs on, and checked examples. `tests/skill.rs` checks that each page names every `public` item of the std modules its `modules` lists and every prelude method of the blocks it covers, so a new method fails the test until it is documented. `lughac skill collections`, now two pages, is exit 2 listing both full names.
- The skill's concepts 11–14 (milestone 232, PRP-264), completing the syllabus: tasks and scopes (`scope`, `spawn`, `join`, `independent`, cancellation, `within`, `Sendable`), channels and actors (the two ends, closing, `select`, actors and when to use which), modules and packages (imports, visibility, re-exports, `lugha.toml`, git packages, `allow = ["ffi"]`, `@test`) and C interop (externs, handles, extern structs, `[link]`, `blocking`, `direct`/`spawned`/`realtime` callbacks, views, the `ffi` grant). `tests/skill.rs` builds multi-file examples from `lugha file NAME` blocks, and runs the libc examples.
- The skill's concepts 6–10 (milestone 231, PRP-263): collections (arrays, `Map`, `Set`), interfaces (declaring, `impl`, interface values, parents, `Display`, `Error` and operators), generics (parameters, bounds, generic types), iterators (`impl Iter<T>`, `for … of`, the helpers) and capabilities (what `main` takes, `Console`, `Fs` and `Dir`, the rest in brief, narrowing, fakes), each with its rules, mistakes and exercises, every example checked by `tests/skill.rs`; `SKILL.md` links them.
- The Lugha skill (milestone 230, PRP-262): `skill/` holds readable, example-first pages on writing Lugha, in the Agent Skills format, so an AI assistant can load them and courses can follow them: `SKILL.md` (how to work, the rules that surprise newcomers, the page index) and concepts 1–5 (values and types, functions, structs and enums, match and patterns, errors), each with prerequisites, rules, common mistakes with their error codes, and exercises. `lughac skill [PAGE]` prints them, `--list` lists them, `--search TEXT` finds lines, and `--export DIR` writes `DIR/lugha/` to upload. `tests/skill.rs` compiles and runs every example. **Breaking:** `lughac spec` is gone, and the spec is no longer built into `lughac`.
- Lock-free callback hold (milestone 229, PRP-261), the item PRP-258 left optional: a `direct` or `realtime` callback with `data` checked that its scope still ran under the runtime's one callbacks lock, on every call, so an audio thread could wait behind another thread registering a callback or ending a scope. Each record now has a counter of calls between check and hold, with stopped and dropped bits, and whichever of the scope's end and a running call finishes last lets go of the captures, decided by one compare-and-swap. Also fixes `LUGHA_RC_REPORT` losing the frees of a C thread that ran only real-time callbacks (it was never listed), which showed captures it let go of last as live.
- `Console` input errors (milestone 228, PRP-260), from the v18 spec review: `console.read_line()` gave a `string` holding whatever bytes stdin had, valid UTF-8 or not, and both it and `read_bytes()` reported a failed read as the end of input. **Breaking:** `read_line()` is now `Result<Option<string>, string>`, as `File.read_line` is, a line that isn't UTF-8 being `Err("line N is not valid UTF-8")` and skipped; `read_bytes()` is `Result<u8[], string>`; a failed read is `Err("stdin: …")`. The runtime hands over bytes and the prelude checks them with `string_from_utf8`.
- `net.only`'s gaps closed (milestone 227, PRP-259), from the v18 spec review: `64:ff9b::a00:1` reached 10.0.0.1 through a NAT64 gateway. NAT64 (`64:ff9b::/96`) and 6to4 (`2002::/16`) addresses are now judged by the IPv4 address inside, and Teredo, local-use NAT64, discard, benchmarking, ORCHID, the IPv4 and IPv6 documentation ranges, old 6to4 relays and site-local addresses are never public. `OnlyNet.resolve` gives only the addresses `connect` would use, and `connect` to one of the host's IP addresses works when a fresh lookup confirms it, so `tls.Options.address` works through `net.only`.
- Review fixes (milestone 226, PRP-258; ledger CAN-13, CBK-08, CBK-09): in a program that never started a task, the first Ctrl-C is held until `main`'s next pause and cancels it there, so its `defer`s run, instead of exiting at once (a loop that never pauses ends at the second, with no checks added); the spec now says a callback without `data` runs whenever C calls it, as the code does, since it captures nothing; and registering a `realtime` callback sets a thread record and C stack aside (`lugha_rt_cb_reserve`), which C's thread's first real-time call takes with one compare-and-swap (`lugha_rt_cb_run_realtime`), allocating nothing and taking no lock.
- Iterators through `impl` (milestone 225, PRP-257; completes ledger INT-03): `for … of`, the iterator helpers and `Iter<T>` values reach a type's iterator only through `impl Iter<T> for X`, never a method merely named `next`; an interface value loops when its interface extends `Iter`. The prelude's iterators (`ArrayIter`, `Mapped`, …, `Map`, `Set`, `Chars`) are blocks now. E0411's help names the missing block. Also fixes codegen looking up a generic interface's block at its unresolved arguments inside a generic instance.
- Small rules (milestone 224, PRP-256; ledger CAP-09a, IMP-07, LEX-01, CAP-18): a plain `for x of xs` may change `xs`, the loop going on over the array it started with (it already held it), so arrays, maps and sets loop by one rule; strings take `\u{…}` escapes as chars do; `make_dir`, `make_dirs`, `remove_file` and `remove_dir` give `Result<(), string>` instead of a meaningless `Ok(0)`; and E0465 is reported only for the program's own `debug` calls, a dependency's compiling to just its value at `-O2`, so a library's stray `debug` never blocks a release build.
- Nominal rules (milestone 223, PRP-255; ledger INT-17, INT-18, INT-21): an interface value converts only to an interface its own extends, never by declaring the same items, as conversions to `Display` and `Error` already worked; a block for a type built from two or more program types (`impl Show for (Point, Line)`) may be written only in the interface's module, closing the case where two libraries that each compiled clashed (E0461) in a program using both; and exactly the built-in names syntax uses are reserved (`Display`, `Iter`, `Error`, the operator interfaces, `FromEntries`, `FromItems`, `Ref`, beside `Option`, `Result`, `Eq`, `Ord`), while `Map`, `Set`, `Console` and the rest may be a module's own.
- One spelling for a generic block (milestone 222, PRP-254; ledger INT-19, INT-20): a generic `impl` names its parameters after `impl`, `impl<T: Num> Grid<T>`, for a program's own type as already for built-in ones, and the parser hands the checker a struct's block as before (`parser::impl_forms`). An interface's parents are joined with `+`, as a bound's are: `interface Store: Eq + Sendable`. New E0214 and E0215 for the old spellings, with the new one as help. Every prelude, std and test program rewritten.
- Guarded views (milestone 221, PRP-253), from the v18 spec review: `p.view(n, f)` in a package other than the program's own needs the `ffi` permission, as an `extern` does (E0333 at its first `p.view`, found by the checker since only it knows the receiver is a `CPtr`), so a package handed a `CPtr` can no longer read or write past C's buffer without being trusted; passing a `CPtr` or taking a view needs no grant. An `n` above `i64::MAX` divided by the element's size panics (`view length too large`) instead of becoming a negative length the bounds check read as huge. The spec now says the memory's lifetime during `f` is the program's to vouch for, beside the length.
- Views of C's memory (milestone 220, PRP-252): `View<T>` reads C's memory and `MutView<T>` writes it, in place and bounds-checked, with `len`, `for`, `slice`, `to_array` and `copy_from`. A view never outlives the call it was given to (E0483), checked on types the way C#'s `Span<T>` is, with no lifetimes. `direct` and `realtime` callbacks take them for C's buffers, so a real-time audio callback fills C's buffer with nothing copied or allocated; `p.view(n, f)` makes one from a `CPtr`. Elements are integers, floats and extern structs holding only those (E0409 otherwise).
- Real-time callbacks (milestone 219, PRP-251), the last §4.8 PRP: `cb: realtime fun(…)` runs as `direct` and is checked at compile time, like Clang's `nonblocking`: the callback and every Lugha function it calls may not allocate (strings, arrays, boxes, capturing closures, array element writes), wait (channels, `select`, `join`, sleeping, actor calls, scopes, I/O, `blocking` externs) or call through a function or interface value. E0482 names what it does and the calls that lead there; a `Ring`'s `try_send` is the way out. It can't take strings or arrays yet (C's call copies them): borrowed views of C's memory come next. VS Code extension 0.39.0
- Rings (milestone 218, PRP-250): `Ring<T>.new(n)` gives `(RingSender<T>, Receiver<T>)`, a fixed ring a callback fills without ever locking, allocating or waiting, even on a thread C made (audio, sensors). `try_send(v)` returns the channel's `TrySend<T>`, so a full ring (`.Full(v)`, the value given back) is visible in the code; there is no `send`. One writer at a time: overlapping `try_send`s panic. The reading end is an ordinary `Receiver`, in `for`, `select` and `merge`. `runtime/select.c` takes `select` out of `chans.c`. Fixed on the way, in the ring's own wake-up: the poller emptied its list of rings before its event counter, so a ring listed in between could wait for ever
- Callbacks on threads C made (milestone 217, PRP-249), the first of two PRPs for C's own threads: a C library calling back from a thread of its own works. Such a thread gets a record and a guarded C stack on its first callback, given back when it exits. A `direct` callback runs there and can never make it wait: anything that would wait panics, reported by the registering scope, while sends that don't wait run as usual; a `spawned` callback becomes a task on the workers. Objects made there come from the system allocator, and `LUGHA_RC_REPORT` counts them. A program waiting on what only C sends isn't declared deadlocked while C may still call
- Every C callback says how it runs (milestone 216, PRP-248): `cb: direct fun(…)` runs during C's call, `cb: spawned fun(W, data)` starts a task in the registering scope on each call, written before `fun` as `blocking` is; one with neither is E0435, and so is `spawned` with a result or without `data`. What a callback does is now visible in its declaration, never implied by its shape. Language server, grammar and the extern snippet know both words (extension 0.38.0)
- Callbacks registered against a scope (milestone 215, PRP-247), the second of three PRPs for callbacks and thread-bound values: a C callback with user data and no result now runs as a task in the scope its extern call ran in, so it may wait (`task.sleep`, channels, other C calls); `cb: fun(W, data) inline` keeps it running during C's call, as callbacks with a result or without `data` always do. Programs drive a C library's event loop from a Lugha loop that yields (`while poll(w) { task.yield_now(); }`), and queued callbacks run in between. A panic in an inline callback no longer ends the program: C gets a zero value, and the registering scope fails by its policy; cancellation waits until an inline callback returns. Once a scope's body ends, C's calls to its callbacks are dropped and their captures freed, without waiting for C's `release`. A queued callback's captures must be `Sendable` (E0475) and it can't take `Ref<T[]>` (new E0481). `independent(f)` handlers receive callback tasks' panics. Language server and VS Code grammar know `inline` (extension 0.37.0)
- Pinned handles and pinned scopes (milestone 214, PRP-246), the first of three PRPs for callbacks and thread-bound values: `extern type Window pinned;` declares a handle its C library allows only on the thread that made it. It is never `Sendable` (E0475), a `blocking` extern can't take or give one (new E0480), and a task that calls an extern taking or giving one stays on its worker from then on. `scope ui pinned { … }` keeps its body, its tasks and the scopes inside them on one worker: the main thread when `main` opens it. A pinned task woken from anywhere goes to its worker's own queue, which no other worker takes from; `main`'s return to the main thread at the end now uses the same queue. Thread-bound C libraries (GTK, OpenGL) no longer need `LUGHA_WORKERS=1`. The language server and the VS Code grammar (0.36.0) highlight `pinned` after an extern type's name. `codegen/source.rs` takes the program's source text out of `codegen/lower.rs`
- Spawning that scales (milestone 213, PRP-245): a finished task's stack waits in its worker's cache (16 stacks) for that worker's next task, its pages kept until the worker has nothing to run, instead of going back to the kernel at once; and each scope counts its tasks in and out, and its owner waits for them, under its own lock instead of the shared one. The live-task list has a lock of its own. Eight tasks each spawning 25,000 in scopes of their own, on four workers: 2.11 s at milestone 212, 1.15 s now; one task spawning 200,000: 9% faster on four workers, about 5% slower on one (recorded in TODO.md). `tests/spawn_stress.rs` checks eight spawners, `limit 2` under contention, the stack cache, and a scope failing while its owner spawns, under ThreadSanitizer too; `bench/measure/scaling` gains `spawners`. Fixed on the way: a false report from ThreadSanitizer on every cross-thread free (a fence it doesn't model)
- Locks of their own for the hot paths (milestone 212, PRP-244): each channel, actor mailbox and task's `join` takes its own lock instead of the one shared lock, which now guards only scopes, cancelling, deadlines, shields and the job room. A waiting task parks still holding its object's lock, let go of once it is saved, and a waker claims it by compare-and-swap before moving a value; `select` locks its channels in address order. Each wait has a generation, so a timeout or socket event arriving after its task was woken otherwise can't wake the task's next wait (possible, rarely, before). Eight ping-pong pairs on four workers: 0.82 s at milestone 211, 0.081 s now. Fixed on the way: a false deadlock while worker threads start; `main` stranded when it finished on another worker just as the main thread parked (a hang); a cancelled cast reading its freed message. `bench/measure/scaling` measures five patterns on 1, 2 and 4 workers
- A scheduler for many cores (milestone 211, PRP-243), the first of two "fast workers" PRPs: each worker has its own queue of ready tasks (256 slots; an idle worker steals half of a busy one's; a shared queue takes overflow and outside wake-ups, checked every 61 picks), and with several workers a task woken by a message runs next on its waker's worker, three times in a row at most. Idle workers spin briefly, then park, by Go's protocol, so no task is stranded; one parked worker polls. Sleepers live in a heap per worker. The scheduler's lock is no longer held across a switch: scheduling takes no lock, and the parking handoff's compare-and-swaps run once workers start. `tests/scheduler_stress.rs` checks 10,000 tasks each run once, ping-pongs while workers steal, a ping-pong beside a busy task, and wake-ups as every worker parks, under ThreadSanitizer too. Single-task benchmarks and four busy tasks unchanged; `chanping` 0.29–0.38 s against 0.18 s at milestone 209 and 0.25 s at 210, a miss recorded in TODO.md
- Tasks on every core (milestone 210, PRP-242), the first of two workers PRPs: tasks run on one worker thread per CPU (`LUGHA_WORKERS=n`, 1 to 256), the main thread first, the others started at the first spawn after lockdown; deterministic and shuffled runs keep one. Every worker takes tasks from one queue under one lock (atomics and a futex, held across task switches); an idle worker runs its own idle loop, one of them waiting in `epoll_wait` for sockets, helper jobs and timers, the others asleep, woken only for work the waking worker won't take. `main` returns to the main thread before the program ends. Every stack Lugha code runs on is aligned to its size, so a function's entry checks `sp & mask` and the step countdown is the top word of the running task's stack: generated code reads nothing kept per thread, safe when a task moves between workers. Each worker has its own C stack with a guard page, and its own signal stack; only the main thread takes Ctrl-C. A task is queued only once it is fully set up (`lugha_rt_task_go`). Four busy tasks run 2× faster on this 2-core machine; single-task benchmarks within 2% (`fib` 12% faster); `chanping` 51% slower (TODO.md). `tests/workers.rs` runs every concurrency program on four workers, and a C harness under ThreadSanitizer
- An allocator for many threads (milestone 209, PRP-241): small blocks come from 64 KiB chunks owned by the worker that carved them, each worker with its own free lists, so its own allocations and frees take no lock or atomic; a block freed on another thread is pushed onto its owner's list for that class with one compare-and-swap and taken back, the whole list at once, before the owner carves more. Chunks come from the reserved region by one atomic add. The runtime's per-thread state, the `Worker` record, now lives in each thread's own storage (`lugha_rt_worker_enter` for a thread that runs tasks). `tests/rc_alloc_threads.rs` has eight threads freeing each other's blocks, also under ThreadSanitizer. Benchmarks within noise, `chanping` 3% slower
- Groundwork for many cores (milestone 208, PRP-240), still on one worker. Every value reaching a second task is marked shared by the side handing it over, before the other can see it: a task's result by the task, an actor's answer by the actor, a failing task's error and message, task names, cancellation reasons, a scope's failure handler, what an actor stored in its state, a handle's buffered bytes, the working folder's `Dir`. Constants become immortal once filled (`lugha_rt_rc_freeze_start`/`_end`), so tasks never contend for their counts. `LUGHA_RC_CHECK=1` (for the build and the run: `LUGHA_RC_CHECK=1 lughac run prog.la`) records which task made each unshared object and ends the program when another counts or marks it; every end-to-end program passes it. Generated code reads and writes counts as LLVM `unordered` atomics, the same instructions. Waiting goes through a parking state: a task can be woken only once its registers are saved, by compare-and-swap once tasks cross threads (`runtime/waiting.c`, split out of `tasks.c`). The scheduler's per-thread state is one `Worker` record. Fixed: a task printing a `Ref` while another printed one could print a cycle twice; each task now keeps its own. Benchmarks unchanged except `chanping`, 13% slower (TODO.md). `CallCosts` became `codegen::Instruments`
- `extern blocking fun` (milestone 207, PRP-239): a C function declared `blocking` runs each call on a helper thread while its task waits (`lugha_rt_c_blocking`), so a slow C call stops only its own task; the wait can't be cut short, since C may use the task's values. A `blocking` extern can't take a callback, `data` or `release` (E0479), and a callback C stored earlier and calls during a blocking call ends the program (`lugha_rt_cb_enter`, at every C entry into Lugha); every declaration of a C function agrees on `blocking` (E0306). Deterministic runs call it in place. The language server marks `blocking` as a keyword after `extern`
- Helper threads (milestone 206, PRP-238): the runtime's blocking work runs on a pool of helper threads while its task waits, so the program's other tasks run: a `Dir`'s and a `File`'s operations (all but `close`), `read_line`, name lookups (`resolve`, `connect`, `listen`) and `Proc`'s `run`, start to exit. Helpers start on demand, after lockdown, at most 16 (`LUGHA_HELPERS`, 1 to 256), block every signal and touch only copies; at most 256 jobs are out at once. A task cancelled meanwhile stops waiting, its job finishing; deterministic runs keep everything inline. A small file read costs about 21 µs instead of 3 µs, a miss recorded in TODO with its fix. `runtime/helpers.c`, `runtime/jobs.c`
- Stacks and C calls (milestone 205, PRP-237): every task's stack, `main`'s included (`lugha_rt_main`), is an 8 MiB reservation carved from regions of 64 stacks, with no guard pages, its pages given back when the task ends; a program can run hundreds of thousands of tasks (the kernel's mapping limit stopped it near 30,000). Each function's entry checks the stack, inserted once the module is optimised; an overflow is a `stack overflow` panic that unwinds, running `defer`s and failing a task's scope, where it used to end the program from a signal handler. Every call of a C function runs on the C stack, the process's own, through a per-call-site thunk (`lugha_rt_c_call`); a C callback that tries to wait panics with `a C callback can't wait: start a task instead`. Cost, interleaved against the previous compiler: mandelbrot +0.4%, nbody +1%, binarytrees and wordfreq unchanged, fannkuch +4%, fib +35% (a call does little else), over the 3% target for the last two: accepted for now, as with hashing.
- Hash seeding (milestone 204, PRP-236): maps and sets hash with SipHash-1-3 keyed by a secret the runtime draws for each process (`getrandom`), instead of FNV-1a, so nobody can choose keys that all collide and make a map quadratic. Results don't change, since maps keep insertion order; hash values do, and differ between runs. Deterministic test runs use a fixed key (from the shuffle seed when shuffled), so they repeat. A string hashes its bytes eight at a time, then its length. `wordfreq` is about 18% slower than with FNV (0.466 s against 0.395 s, interleaved runs): over the Draft's 10% target, accepted for now, with the optimisations noted in TODO.md.
- Deterministic tests (milestone 203, PRP-235), the first of phase 6: a plain `@test` runs on virtual time, which starts at 0 and jumps to the earliest timer once every task waits and no socket has anything ready, so sleeps, `after`, deadlines, shields and socket timeouts cost no real time. `lughac test --shuffle=SEED` also picks each next ready task, and `select`'s ready arm, at random from the seed (`--shuffle` alone draws a seed and prints it): a test depending on one order fails under some seed, the same way every time, reported `FAILED (seed N)` and as `"seed"` in `--json`. Integration tests keep real time and order. The runner passes the mode in `LUGHA_SCHED`; reporting moved to `src/driver/test_report.rs`.
- Generic actors and actors as interface values (milestone 202, PRP-234): `actor Cache<K: Key + Sendable, V: Sendable> { … }` (every parameter bounded `Sendable`, E0475 otherwise); each instance, `Cache<string, i64>`, is its own handle type with its own messages, generated per instance. `impl Store for Users { … }` for an actor makes its handle implement `Store`: the block's methods run inside the actor as messages and may be called on the handle directly; a handle converts to `Store` and meets `T: Store` bounds, and a call through the `Store` value sends the message (`lugha_actor_<Type>.<method>$send` fills the table's slots). `Store`'s defaults run inside the actor too. A generic actor's block is written `impl Source<T> for Queue<T: Sendable>`. An actor's methods still can't have type parameters of their own (E0439).
- Function types are interfaces (milestone 196, PRP-228): every function value has a type of its own, the struct of what it captured, implementing its signature's interface `fun(A): R`. `<F: fun(i64): i64>` takes the exact function: each closure or named function passed gets its own instance, which calls it directly; a plain function value gives the shared `fun(i64): i64` instance as before. `interface Pricing: fun(i64): i64 {}` names a kind of function whose values are callable, and `impl fun(i64): i64 for Scale { fun call(self, x: i64): i64 = … }` makes a struct callable and convertible to the function type. Existing programs build and run unchanged.
- The memory measurement (milestone 192, PRP-224), the prototype's last part: under `--memory=rc` small objects come from free lists by size class, a local is released after the last statement mentioning it, and an `if` or `match` hands a fresh value through without counting it. For both memory models, an enum's payload is addressed so LLVM keeps it in registers (binarytrees under the collector: 1.18 s to 0.66 s, 72 MB to 38 MB), and the runtime is compiled at `-O2` (it had no optimization flag; chanping 0.28 s to 0.11 s). `LUGHA_CALL_COSTS=1` simulates the stack check and scheduling countdown later phases add, for `bench/run.py`'s `lugha-rc-calls` column; `bench/measure/pauses.la` measures the longest pause. `bench/RESULTS.md` holds every measurement and the recommendation; DECISIONS.md holds the open question.
- Reference counting across tasks (milestone 191, PRP-223), the prototype's second part: under `--memory=rc`, programs with tasks, channels and actors build and free what they make. A value crossing to another task (sent, spawned with, passed to an actor, joined) is marked shared, everything local it reaches with it, and its count changes atomically from then on; the inline check for a local count stays one compare. Channels, tasks and actor handles are counted. Only C callbacks are still refused. `bench/` gains `chanping`, a channel ping-pong in Lugha, C, Rust and Go.
- A reference-counting prototype (milestone 190, PRP-222), the first part of v18's memory decision: `lughac build`, `run` and `test` with `--memory=rc` (or `LUGHA_MEMORY=rc`) build without Boehm. Every object gets a 16-byte header (its drop and its count); copies add a holder, temporaries end with their statement, locals with their block, values move on their last use, copy-on-write tests the count, and constants are immortal. `LUGHA_RC_REPORT=1` prints how many objects were made, freed and are still live at exit (`2` lists them); `LUGHA_RC_POISON=1` turns a use after free into a panic. A program using tasks, channels, actors or C callbacks is refused under it (exit 2). Every other end-to-end program prints the same under it and frees everything, except the gaps `tests/rc_programs.rs` lists. `bench/run.py` gains a `lugha-rc` column. Without the flag nothing changes.

### Breaking
- `--target aarch64-unknown-linux-gnu` builds through zig (milestone 247, PRP-281), not `aarch64-linux-gnu-gcc`: install zig 0.17.0 or newer, or set `LUGHA_CC=aarch64-linux-gnu-gcc` to keep the old compiler. The default `--target` is now the machine lughac runs on (unchanged on x86-64 machines).
- An iterator needs `impl Iter<T> for X { fun next(mut self): Option<T> … }`: a type with only its own `next` no longer loops (milestone 225).
- `make_dir`, `make_dirs`, `remove_file` and `remove_dir` return `Result<(), string>`: code matching `.Ok(n)` on them now gets `()` (milestone 224).
- An interface value no longer converts to another interface by having its items: write `interface J: I`. A block for a type of several program types moves to the interface's module or behind a wrapper struct. A program's own `Display`, `Iter`, `Error`, `Add`…`Neg`, `FromEntries`, `FromItems` or `Ref` is E0302: rename it (milestone 223).
- `impl Grid<T: Num> { … }` and `impl Show for Grid<T>` are E0214: write `impl<T: Num> Grid<T>` and `impl<T> Show for Grid<T>`. `interface I: A, B` is E0215: write `interface I: A + B` (milestone 222).
- A package without the `ffi` permission can no longer call `p.view` (milestone 221): grant it, or have a granted package make the view.
- `c_read` and `c_write` are gone (milestone 220): `p.view(n, fun(v: View<u8>) = v.to_array())` reads, `p.view(n, fun(v: MutView<u8>) { v.copy_from(bytes); })` writes, and `slice` takes an offset. Callbacks no longer take `Ref<T[]>` (take `MutView<T>`), and `direct` and `realtime` callbacks no longer take `T[]` (take `View<T>`; `spawned` ones still take the copy): E0484. E0481 is no longer reported.
- A `direct` callback with `data` must capture only `Sendable` values, as a `spawned` one already did (milestone 217): it may run on a thread C made. One collecting results into a `Ref` sends them on a channel instead; passing a function value whose captures aren't known (a `fun(…)` variable) is E0475
- Every extern callback declaration needs `direct` or `spawned` before its `fun` (milestone 216): a callback milestone 215 queued (with `data`, no result, unmarked) is now `spawned fun(…)`; every other one, and every `fun(…) inline`, is `direct fun(…)`. `inline` after a callback's type is a parse error pointing at the new spelling
- A C callback with user data (`data`) and no result now runs after C's call returns, as a task (milestone 215): one that must run during the call (an `each`-style iteration writing into its captures) needs `inline` after its type, `f: fun(string, data) inline`. Such a callback capturing a value that isn't `Sendable` (a `Ref`) is E0475 until marked `inline`. A panic in a callback no longer ends the program with 101 at once: C gets a zero value and the registering scope fails (the root scope: 101 when `main` returns). The panic for an inline callback that waits now reads `an inline C callback can't wait: …`
- With several workers (milestone 210), tasks run at the same time, so the order in which different tasks print or act isn't fixed any more; a `println` still prints its line whole. A program relying on one order, or calling a C library that needs one thread, runs with `LUGHA_WORKERS=1`
- Actors in scopes (milestone 201, PRP-233): an actor starts in a scope, `s.spawn(Counter { count: 0 })` or `root.spawn(…)` with `main`'s root scope; bare `spawn Counter { … }` is E0474. The scope stops its actors once its body and other tasks are done (after their queued messages) and waits for them; leaving early, a failure, a deadline or Ctrl-C cancel them with the tasks (a handler unwinds, running its `defer`s). An actor runs as a task of its scope, so its panic fails the scope as a task's does, or is reported under `independent`; a caller of a panicked actor still panics. `join()` on an actor is gone (E0415, with help): the scope reports how it ended. Mailboxes are bounded: 1,024 messages, or `actor Logger mailbox 10_000 { … }` (E0439 for anything but a positive literal); a call or cast to a full mailbox waits for room, and `stop` is queued past the limit. Actors don't count toward `limit n`. The C harness's four actor cases in `tests/tasks_runtime.rs` became end-to-end programs.
- Channels with two ends (milestone 200, PRP-232): `Chan<T>.new(n)` makes a channel and gives `(Sender<T>, Receiver<T>)`, the capacity required (`0` hands each value over directly); `Chan<T>.unbounded()` has no limit. `Chan.new()` and `Chan.buffered(n)` are gone, and `Chan<T>` is no longer a type (E0305, with help). Only a `Sender` sends, tries to send and closes; only a `Receiver` receives (E0415 on the other end, with help), also in `select`. `for x of rx` runs until the channel is closed and empty. `tx.try_send(v)` gives `.Sent`, `.Full(v)` or `.Closed(v)`, and `rx.try_recv()` gives `.Ready(v)`, `.Empty` or `.Closed` (the prelude's `TrySend` and `TryRecv`; it was an `Option`). `s.merge(receivers)` makes one receiver fed by several, closing once all are. A channel keeps where it was made, and a deadlock report lists each waiting task or actor with its channel's place. The VS Code extension's `chan` and `spawn` snippets follow (0.35.0), and its grammar knows `Sender` and `Receiver`.
- Time and shutdown (milestone 199, PRP-231): a scope may have a deadline, `within ms` or `until t` (monotonic milliseconds, `clock.monotonic_ms()`'s clock; both at once is E0477), never later than its enclosing scope's. Once it passes, the body and the scope's tasks are cancelled with `.Deadline`, waiting or busy, and the scope fails with `f.kind` `.Deadline` unless a failure came first; `s.remaining()` gives the milliseconds left (`None` without a deadline). `shield within ms { … }` holds cancellation off while its block runs, at most `ms`, then lets it in; `shield` without `within` is E0211. A shield in a `defer` running for a cancellation is cut off at its deadline by an unwind its own landing pad stops, so the code after it still runs (a shield with a value cut off so ends the program, exit 101). The first Ctrl-C cancels the root scope's tasks and `main` with `.Shutdown`, their `defer`s run, and the program exits 130; a second, or one in a program that never started a task, exits 130 at once. A task parked in the scheduler is now woken when the scheduler itself cancels it. `FailureKind` gains `.Deadline` and `Reason` `.Deadline` and `.Shutdown`, so a `match` on them needs the new arms.
- Scope policies (milestone 198, PRP-230): a scope's settings come between its name and its body: `independent` reports each failing task (printed, naming it) and runs on, `independent(f)` gives each failure to `f`, and `limit n` makes `spawn` wait while `n` tasks run; `scope<E> s` fails with `Failure<E>`, every task's error converting to `E` (E0478); another or a repeated setting is E0477. `Failure` is now a struct, `{ task, kind }`: match `f.kind` for `.Error(e)` or `.Panic(m)`, and `f.task` names the failing task, `t.name(…)`'s or the called function's. A scoped task's panic is no longer printed as it happens; a root task's failure prints in full (``task `bad` failed: …``) before the program exits 101. Under the hood a scoped task's entry catches its own unwind (`runtime/scope_policy.c`).
- The sendable rule (milestone 197, PRP-229): a value crossing to another task must be `Sendable`, worked out from its parts (the prelude's `auto interface Sendable` and its derive blocks), so a `Ref` can never reach two tasks. Checked at a spawned call's arguments, captures and result, at every `Chan<T>` written or made, and at an actor's fields, messages and replies (where E0439's own sharing rule was). A function value is sendable when its captures are; an interface value when its interface requires `Sendable`; a `T` when bounded `T: Sendable`. The capabilities, what they open and `Error` require `Sendable`, so a fake `Console` or `Conn` recording into a `Ref` must keep that in an actor. `std.http`'s servers take a `Handler` (`fun(Request): Response` that is `Sendable`). New errors: E0475 (not sendable, naming the part), E0476 (`impl Sendable`, `with Sendable`, `auto` outside the prelude). The library's files, sockets, TLS handles and test `Entropy` keep their shared state in runtime cells (`runtime/cells.c`) instead of `Ref`s. Programs sharing a `Ref` between tasks now use a channel or an actor; E0438's hint no longer suggests a `Ref`.
- Scopes and cancellation (milestone 195, PRP-227): every task starts in a scope. `scope s { … }` is an expression of type `Result<T, Failure>`; `s.spawn(work(x))` starts a task in it, and `main` and tests may take the root scope by type (`root: Scope`). A scope waits for its tasks; the first failure (a task's panic or `Err`, or a panic in the body) cancels the others and the body with `.SiblingFailed`, and is the scope's `Err`; leaving the body early (`return`, `?`, `break`, `continue`) cancels them with `.Parent`; at the body's end the scope waits for its tasks before the body's `defer`s run. Cancelling is invisible: a cancelled task unwinds silently, running its `defer`s, at its next pause point (channels, `join`, `select`, sleep, socket waits) or preemption point. `join()` gives `Result<V, Stopped>` (`V` a `Result`-returning task's `Ok` type); `t.cancel(why)` and `t.name(text)` are new. `Scope`, `Failure`, `Stopped` and `Reason` are prelude types. A task's panic no longer ends the program: it fails its scope; a root-scope task's failure cancels the rest and `main`, which unwind, then the program exits 101. `main` returning waits for the root scope's tasks. Bare `spawn f()` is E0474 (`spawn` alone starts actors); handles are second-class, so a `Task` in an array, a field, a returned value or a closure is E0472, and `x.spawn` on a non-scope E0473. A task's `Err` type must implement `Error`. `std.http`'s servers run each connection in one scope: a connection's panic ends the server with an `Err`. Rewrite `let t = spawn f(x); t.join()` as `let t = s.spawn(f(x)); t.join().unwrap()` in `scope s { … }`, or through `root`.
- Unwinding (milestone 194, PRP-226): a panic runs the pending `defer`s and lets go of what each frame of its task holds, innermost first, after printing its message; the program then exits 101, or in an actor only the actor ends, now with nothing left held. A spawned task's panic ends the program once that task has unwound. A panic inside a `defer` while unwinding ends the program at once; a stack overflow doesn't unwind; a panic never unwinds into C (a callback's unwinds, then the program ends). Built on unwind tables: only calls with something to clean up get a landing pad (libgcc's personality and unwinder), so a function like `fib` is unchanged. A flat `match`'s missing-key panic and the `panic` intrinsic now release what they hold while unwinding.
- Reference counting is the only memory model (milestone 193, PRP-225): the Boehm collector is gone (`third_party/bdwgc/`, its compile and link step), and so are `--memory` (now an unknown argument, exit 2) and `LUGHA_MEMORY`. Every program counts holders and frees each object when its last one goes. `Ref` boxes holding each other in a cycle are never freed, and a panicking actor keeps what its frames held, until a cycle collector and unwinding exist. A value returned from inside `for … of mut` through a type's `index` is its own copy and doesn't see the element handed back afterwards (`interfaces/read_modify_write/loops.la`). C callbacks hold their closure's environment until C releases them; `Dir` and SHA-256 handles are closed and freed with their last holder. Counting keeps `-O0` frames close to the collector's: a temporary taken where it was made and a fresh argument need no slot, a `match` arm that leaves the matched local alone borrows its bindings (an arm reassigning it no longer reads freed memory), and releases read only the counted fields of a value where it lies. `LUGHA_RC_REPORT` and `LUGHA_RC_POISON` keep working; `LUGHA_CALL_COSTS=1` stays for the benchmarks' `lugha-calls` column.
- Process lockdown (milestone 189, PRP-221): once the runtime has made what `main` (or a test) took, the kernel limits the whole process, C code and started programs included, to those capability kinds: no sockets without `Net`, no new processes without `Proc`, no files without `Fs` beyond what `Net` and `Clock` read (name lookup, certificates, zone files; `Proc` reads everything). seccomp refuses with `EPERM`, never a kill, and always refuses `io_uring`; Landlock limits files. Applied as far as the kernel supports, quietly; `LUGHA_LOCKDOWN=report` prints what applied. C code that did these things without the capability now fails.
- The `ffi` permission (milestone 188, PRP-220): a package declaring C code (`extern fun`, `extern type`, or a `[link]` table) builds only when the program's `lugha.toml` grants it `allow = ["ffi"]` on its entry, or on a package that depends on it: a grant covers the package's dependencies too. Otherwise E0333 (new) at its first declaration, with help naming the entry to change; nothing in its `[link]` table is compiled. Only the program's manifest grants (`allow` elsewhere is E0321). `lugha.lock` gains an `[ffi]` table naming each package that may run C and the grant that lets it, and `lughac update` prints `zlib now runs C code, through `sqlite`'s ffi grant` when an update widens that reach. The program's own code and the bundled prelude and std need no grant.
- `Dir` confinement (milestone 186, PRP-218): every `Dir`, `fs.cwd()`'s too, reaches only its folder and below, enforced by the kernel: each path is opened with `openat2` and `RESOLVE_BENEATH | RESOLVE_NO_MAGICLINKS`, so `..` above the folder, absolute paths and symbolic links leading out are `Err("path leads outside the folder")`, even when a folder is swapped for a link mid-lookup. `fs.cwd().read_file("/etc/hosts")` becomes `fs.dir("/etc")?.read_file("hosts")`. New: `fs.dir(path)` (any folder, the one unconfined lookup), `dir.dir(sub)` (a narrower `Dir`) and `dir.read_only()` (every writing method `Err("the folder is read-only")`). A fake `Dir` implements `dir` and `read_only`. Without `openat2` (Linux before 5.6) every `Dir` operation fails rather than running unconfined. The test runner's folder is now kernel-confined too.
- Tests' capabilities (milestone 185, PRP-217): a plain `@test` is given stand-ins: a fresh temporary `Dir` (removed afterwards; absolute and `..` paths refused), a `Clock` stopped at 2000-01-01T00:00Z, an empty `Env`, an `Entropy` seeded from 0 and a `Net` limited to loopback; it runs in its folder. `Fs` and `Proc`, and the real world, only go to `@test(integration)` tests, which run under `lughac test --integration` and are reported skipped without it; a plain test taking `Fs` or `Proc` is E0434. The command-line types moved from `src/driver/mod.rs` to `src/driver/cli.rs`.
- TLS over any `Conn` (milestone 184, PRP-216): OpenSSL runs on memory buffers and `std.tls` carries the bytes over the `Conn` a `Net` gives, so a fake `Net` covers TLS and `https://` too and the C side never touches a socket or a file. Certificates, keys and trusted CAs are PEM text, read by the program through a `Dir`: `tls.listen(net, addr, cert_pem, key_pem)`, `http.serve_tls(net, addr, cert_pem, key_pem, handler)`, and `Options.ca_pem` (was `ca_file`, a path). `tls.Conn` and `tls.Listener` are `tls.SecureConn` and `tls.SecureListener`, which are a `Conn` and a `Listener`; a server wanting `peer_key()` accepts with `accept_secure()`. New: `tls.client(conn, host, opts)`, `tls.client_keys(conn, keys, timeout_ms)` and `tls.server(conn, cert_pem, key_pem)` run TLS over a connection made any way. An encrypted private key fails to load instead of prompting for a passphrase.
- Capabilities, fourth step (milestone 183, PRP-215): the network needs a `Net`, which `main` and tests take by type. `std.net` is gone: `net.listen(a)`, `net.connect(a)`, `net.connect_timeout(a, ms)`, `net.resolve(n)`, `net.udp_bind(a)`, `net.udp_bind_shared(a)` and `net.interfaces()` are the same calls on a `net: Net`, and `net.Conn`, `net.Listener`, `net.Udp` and `net.Interface` are the prelude's `Conn`, `Listener`, `Udp` (interfaces, so a fake `Net` hands out fake connections) and `NetInterface`. Every `std.http` and `std.tls` function that connects or listens takes the `Net` first: `http.get(net, url)`, `http.serve(net, addr, handler)`, `tls.connect(net, addr)`. HTTP's plain connections go through the `Net`, so it runs over a fake; `std.tls` still opens the runtime's own sockets until TLS runs over any `Conn`.
- Capabilities, third step (milestone 182, PRP-214): files and folders go only through a `Dir`. `std.fs` is gone: its functions are methods of a `Dir` from `fs.cwd()` (`dir.make_dirs(p)`, `dir.exists(p)`, `dir.size(p)`, `dir.rename(a, b)`, `dir.set_mode(p, m)`, `dir.sync(p)`, `dir.open(p)`, `dir.create(p)`, `dir.append(p)`, …), `fs.list_dir(p)` is `dir.list(p)`, and `fs.File` is the prelude's `File` interface (`read`, `read_line`, `write`, `write_text`, `close`). `read_bytes`, `write_bytes` and `append_bytes` are `Dir` methods; `read_stdin_bytes()` is `console.read_bytes()` and `flush()` is `console.flush()`; calling the old intrinsics is E0471. A fake `Dir` implements the core methods; `write_file`, `append_file` and `make_dirs` are default methods over them.
- Capabilities, second step (milestone 181, PRP-213): the clock, the environment, other programs and the system's randomness need capabilities. `main` and tests may take `Clock` (`now_ms`, `monotonic_ms`, `local_offset`), `Env` (`get`), `Proc` (`run`, `run_with`, `call`, giving the prelude's `ProcessOutput`) and `Entropy` (`bytes`, `next_u64`) by type, like `Console`; each is a prelude interface, so a fake is a type that implements it. `std.env` and `std.process` are gone: `env.get(n)` is the same call on an `env: Env`, `env.current_dir()` is `fs.cwd().path()` (new), `env.set_current_dir` is gone (the working folder never changes), `process.run`/`run_with`/`call` are `proc.run`/`run_with`/`call` and `process.Output` is `ProcessOutput`. `time.now_ms()`, `time.monotonic_ms()` and `time.local_offset(ms)` are `clock.now_ms()`, `clock.monotonic_ms()` and `clock.local_offset(ms)` (its error a `string`; `std.time` keeps its calendar). `random.from_os()` is `random.from_entropy(entropy)`. `crypto.random_bytes(n)` is `entropy.bytes(n)`, and `crypto.ed25519_keypair` and `crypto.x25519_keypair` take an `Entropy`, so a fake gives the same key every time. `hpke_seal` and TLS still draw one-time keys from OpenSSL's generator.
- Capabilities, first step (milestone 180, PRP-212): a program touches the world only through values `main` is given. `main` takes, by type and in any order, `string[]` (the arguments), `Console` and `Fs`, returning `()` or `i32`; `@test` functions take `Console` and `Fs` too. `print`, `println`, `eprint`, `eprintln`, `read_line`, `read_file`, `write_file`, `append_file`, `args` and `exit` are gone from programs (E0471, new, naming the capability): write `console.println(x)` (any `Display` value), `fs.cwd().read_file(p)`, and return the exit code from `main`. `Console`, `Fs` and `Dir` are prelude interfaces met by `impl`, so fakes are ordinary types, and capabilities may be sent to actors. A `Dir` isn't confined yet. E0304 and E0434 name what `main` and tests may take. Also: an expected interface no longer types an operator's operands or a bare `T` result (`console.println("a" + s)`, `console.println(xs.iter().fold(…))`), and printing `()` names `.debug()`.
- Collection literals (milestone 178, PRP-210): maps and sets are written `Map { "ann": 31 }`, `Set { 1, 2 }`, `Map {}` and `Set {}`, typed from context or type arguments (`Map<string, i64[]> {}`); keys are expressions, and a bare key name nothing defines gets help to write it as a string. The prelude interfaces `FromEntries<K, V>` and `FromItems<T>` give any type these forms (`Bag { "apple", "pear" }`); in the module that declares such a type its braces stay its fields. `#{…}` is gone (E0213, new); braces that can't build their type are E0470 (new). Maps and sets print as `Map { "a": 1 }` and `Set { 1, 2 }`. A literal after a type name in a condition needs parentheses whatever it holds (E0205).
- Type arguments at uses, and `as` only without loss (milestone 177, PRP-209). Type arguments may be written after a name or member name: `pick<string>([])`, `bigger<i64>` as a value, `xs.map<string>(f)`, `Stack<i64>.new()`, `Chan<Job>.new()`, `Ref<f32>.new(1.5)`, `Pair<u8> { … }`, `Shape<f64>.Circle(r)`, `Option<i64>.None` and `Option<u8>.Some(7)`; `_` leaves one to inference; a wrong count, or any on something without type parameters, is E0418. `<` reads as type arguments only when a closed type list is followed by `(`, `.`, `{` or the end of an expression, so `f(a < b, c > (d))` now passes type arguments. `as` converts numbers only where nothing can be lost (widening, exact integer-to-float, `f32 as f64`, `char` code points, `u8 as char`, fitting literals); anything else is E0469 (new). The losses are named by methods taking the target as a type argument: `try_into<U>()` (an `Option`, also to `char`), `truncate<U>()` (low bits), `saturate<U>()` (clamped; floats toward zero, NaN as 0, as `as` was), and `round`, `floor`, `ceil` (which panic with `conversion out of range` when the result doesn't fit). `Stack::<i64>` is E0207 with help. E0412's help suggests writing type arguments.
- Enum variants in patterns take a leading dot (milestone 176, PRP-208): `.Some(x)`, `.None`, `.Ok(v)`, `.Circle(r)`, in `match`, `if let`, `while let` and `let … else`, at any depth. A bare name in a pattern is always a new binding, at the top level too (`other => …`). `Circle(r)` without the dot is E0212 (new) and a bare `None` against an `Option` is E0468 (new), so old patterns can't silently become catch-alls; `mut None` is E0468, no longer E0428. Missing cases in E0417 print with dots, and the language server's fixes write them. An arm whose value is a block now ends at its `}`. Values are built as before (`Shape.Circle(1.0)`, `Some(3)`).
- A discarded `Result` is an error (milestone 175, PRP-207): an expression statement of type `Result` is E0467 (new); handle it with `?` or `match`, or write `let _ = f();` to drop it on purpose. E0456's page now shows `let _ =` inside `defer { … }`.
- The prelude's methods on built-in types are blocks of each type's own methods (milestone 172, PRP-204): `impl string { fun trim(self) … }`, `impl<T> T[] { fun map<U>(self, f) … }`, `impl char`, `impl<T> Option<T>`, `impl Result<T, E>`, replacing the method-name table. Programs call them as before; the free functions behind them (`map(xs, f)`, `str_trim(s)`, `option_map(o, f)`) are gone (E0301). Hover and go to definition now reach the prelude's methods.
- Operators go through generic interfaces (milestone 171, PRP-203): `a * b` calls the `mul` of `a`'s type's `impl Mul<B> for A`, chosen by `b`'s exact type, and the block's method decides the result. Own `add`/`mul`/… methods, several same-named ones per type and `impl f64 { fun mul(self, v: V): V }` (now E0466; E0458 retired) become `impl Add for V`, `impl Mul<f64> for V` and `impl Mul<V> for f64` (in `V`'s module). An operator on an interface value is E0404; a bound gives an operator only when it is an operator interface (`T: Mul<f64>`).
- Printing needs `Display` (milestone 170, PRP-202): `print`, `println`, `eprint`, `eprintln`, `to_string` and `"{x}"` take a value whose type implements `Display`: the numbers, `bool`, `char`, `string`, and structs and enums with `impl Display for T { fun show(self): string … }`. Arrays, tuples, `Option`, `Result`, maps, sets, `()` and structs or enums without it are E0422, with help to write `x.debug()` for the old text. A type's own `show` method becomes `impl Display for T`, and is no longer used inside another value's text. `unwrap()` on an `Err` shows the error's debug form (`"boom"`, quoted). `debug` is a reserved name.
- `Ord` is an interface (milestone 168, PRP-200): `interface Ord: Eq { fun cmp(self, other: Self): Ordering; }`. A struct or enum ordered with `<`, `sort`, `min` or `max` needs `with Ord` (fields in order, variants in declaration order; implies `Eq`) or `impl Ord for T { … }`; an own `cmp` method no longer orders it (E0422). Floats keep `<` but aren't `Ord`: `[1.5].sort()`, `math.min(1.5, 2.0)`, and tuples or structs holding a float that are ordered are E0451, with help naming `f64.total_order`. E0419 is no longer reported for `Ord`: E0422 or E0451 instead.
- `Eq` and `Key` are asked for (milestone 167, PRP-199): a struct or enum compared with `==`, used in `assert_eq`, or used as a map key or set value needs `with Eq` or `with Key` (`with Key` implies `Eq`), or `impl Eq`/`impl Key` by hand; own `eq` and `hash(self, h: u64): u64` methods no longer count. Hashing is `fun hash(self, mut h: Hasher)`. Floats are `Eq` but not `Key`. E0441 and E0454 are retired.
- Deriving is on request (milestone 165, PRP-197): a struct or enum is JSON, or meets a program's own derivable interface, only with `with I` after its declaration, `impl I for T = derive;`, or a hand-written `impl I for T { … }`; a type's own `to_json` or `show` no longer replaces a derived item. `Eq` is still automatic. `json.Json`'s hidden `$missing` is now the public `missing(path, field)`.
- Interfaces are nominal (milestone 164, PRP-196, the first of v18): a type implements an interface only through `impl I for T { … }`, so a type that met one by having its methods needs the block, and those methods move into it. The prelude's interfaces (`Eq`, `Ord`, `Iter`, `Display`, the operators), indexing and derivable ones (`json.Json`) are still met by method names until their own milestones. A number, string or array converted to a program's interface (`let x: Any = 1;`) is E0422 until built-in types can implement interfaces. E0430 is retired: two implemented interfaces sharing a method name is E0460.
- Programs that load `std.tls`, `std.http` or `std.crypto` need OpenSSL 3.2 or newer (E0332 otherwise); Ubuntu 24.04's OpenSSL 3.0 is too old.
- `crypto.CryptoError` has two new variants, `NotAuthentic` and `BadKey(string)`: a `match` naming every variant must add them.

### Fixed
- On Windows, a read or write cut short by its deadline could abort another task's read or write on the same socket, which then failed with `Input/output error` (seen on CI's Windows runner, never under Wine). An operation aborted though its own task never cancelled it moved nothing, so it is now started again; an aborted operation's error, should one surface, reads `Operation canceled`.
- On Linux and macOS a socket held one waiting task: a second waiter, another reader or a writer while a task read, replaced the first, which then hung until its timeout. Eight tasks accepting on one listener never all returned, and a task reading a connection while another wrote to it until it filled stalled both. Each socket now has a reader's and a writer's place in the poll, armed together (both directions at once on Linux, two filters on macOS), and the poll reports which directions are ready; more tasks waiting the same way take turns, first come first served, the next woken to try again whenever one's wait ends. Closing a socket empties its places, so one given the same number starts afresh (`tests/programs/runtime/socket_waits/`). Windows waits per operation and was never affected.
- A nested scope's deadline or failure cancelled the tasks of every scope its owner had open, so a task of the enclosing scope was stopped silently and that scope ended `Ok` without waiting for it (`scope s { s.spawn(work()); scope t within 50 { … } }` lost `work`). A cancellation made by a scope now reaches only that scope and the scopes inside it, as the spec says; a task spawned into an enclosing scope while the owner unwinds to the inner one isn't cancelled either (`tests/programs/concurrency/deadlines/inner_only.la`, `scopes/inner_failure.la`).
- A program could end with `panic: deadlock: every green thread is waiting` while a task was about to run: the last worker to park checked the run queues, inboxes and timers one after another, and a timer fired between those checks (the poller moving a sleeping pinned task into its worker's inbox) left every check true. The check now also confirms no parked worker was woken since it parked; one that was woken checks again when it parks. Seen once in CI (`tests/pinned.rs`).
- The runtime on a real Mac (milestone 253), found by running CI's first helper-thread program there and checking the macOS layer against XNU's source (`docs/research/macos.md` §7): a job finished on a helper was never collected, so `proc.run` and every other helper operation hung on macOS (kevent replaces an event's `udata` on every change, and the wake-up carried `NULL`; its token is now read from the event's `ident`); a helper's write to a pipe whose reader was gone (a program started with input that exits without reading it, a file stream on a FIFO) ended the program with SIGPIPE on macOS, which sends it to the process, not the writing thread (`F_SETNOSIGPIPE` on those descriptors); a C stack overflow died by SIGBUS instead of `panic: stack overflow`, as macOS reports a guard-page fault as SIGBUS (both signals handled, on every system); a program started with stdin, stdout or stderr closed opens `/dev/null` there first, on every system, so a pipe can't take that number and starting a program keeps working; macOS's open-file limit of 256 is raised to 1024 (never past the hard limit); UDP's 64 KiB overflow area is one for the process, not one per thread. CI's Mac job gives each case a minute, runs `start` with stdin closed, and has a case whose child ignores 1 MiB of input. A build for macOS no longer leaves an empty `a.o` where it runs: `zig cc --version` writes one for a macOS target, so the compiler's version is asked in an empty folder of its own.
- macOS's POSIX gaps (milestone 252, PRP-286): a UDP datagram longer than `recv_from`'s `max` was cut short silently on macOS, which ignores `MSG_TRUNC` as a flag; on both systems it is now one `recvmsg` into the caller's buffer and a 64 KiB area behind it, so the datagram's real length always comes back (`Err("datagram of N bytes is longer than max")`). Starting a program on macOS needed `pipe2` (macOS 27): pipes are now `pipe` + close-on-exec there, and every start uses `POSIX_SPAWN_CLOEXEC_DEFAULT`, so a started program inherits only what it's given. Joining a multicast group uses `MCAST_JOIN_GROUP` with `group_req` on both systems (Linux's `ip_mreqn` was Linux's). Sleeps, timeouts and deadlines on macOS use `CLOCK_UPTIME_RAW`, which stops while the Mac sleeps as Linux's monotonic clock does. CI's Mac job runs two more cases.
- A task's `sleep`, or a socket wait, could be lost on several workers: a timer (or a socket becoming ready) firing in the moment between the task arming it and publishing its wait couldn't claim the wait, and was dropped. The task then waited for ever, and once all else was idle the program died with "deadlock: every green thread is waiting" (about 1 run in 100 of `tests/pinned.rs` on a loaded machine; 0 in 1,000 since). Such a wake-up is now noted on the task, and its wait, once published, ends at once (`tests/waiting_runtime.rs`).
- A narrowed network (`net.only("localhost:8080")`) tried only the first allowed address its host resolved to, so where `localhost` gives `::1` first, a server on `127.0.0.1` was missed ("Connection refused") while a plain `connect` reached it. It now tries each allowed address in turn, each one it checked, and returns the last error when none answers (`tests/programs/capabilities/narrowing/each_address.la`).
- A direct callback that tried to wait on a thread C made (a `send` to a full channel, a `recv`, a `select`, a `sleep`, a `join`, an actor call) crashed the program later, when the channel or task was freed: the refusal panicked after the wait had put itself on a queue, leaving a record on a stack the panic unwound. Every wait now asks before it registers anywhere, so the refusal (C gets 0, the scope fails) leaves nothing behind; also for a direct callback on C's own stack (`tests/foreign_threads.rs`).
- From lugha-dev's review at 0.18.1 (milestone 246, PRP-280): a closure given to a `Result`'s `and_then` takes its error type from what's expected, so `good.and_then(fun(n) = Ok(n + 1))` types without writing the closure's return type, and an `if` in such a closure whose one branch is `Err(…)` or `None` takes the other branch's type; every diagnostic names its file by its path from the program's package folder (`src/shapes.la`, `test/a_test.la`), in `lughac test` and for modules other than `build`'s main file too, where it was named from its own folder (`shapes.la`); E0424's explanation no longer says `main` returns nothing, and E0429's writes `let .Some(n) = o else` and no longer names `exit`; the spec states that a function value's `.debug()` is `<fun>`.
- A cancel landing just before a task parked was missed (PRP-279): the canceller saw the task not yet waiting and woke nothing, and the task then waited for nothing, until something else woke it or the program deadlocked. A parking task now looks at its cancellation once its wait is published, and the canceller fences between storing the cancel and looking, so one of them always sees the other.
- Five compiler bugs from a reader's review (PRP-276): **Breaking:** `with Key` or `with Ord` beside a hand-written `impl Eq` is E0463, since both derive `Eq` and a written `eq` broke the key or order laws silently; `sum` works on an iterator of a `T: Num` or `T: Float` parameter; an enum's associated function is a value, as a struct's is (`E.make`); E0417 prints a tuple's missing case as `(false, false)`, not `.()(false, false)`; `lughac check` takes a file with `fun main` inside its package's `source` folder as a main file, as `run` does, and E0312 inside a package that imports it by its own name says to drop the name. The spec now agrees with itself that a derive block for one built-in type gives methods (`5.show()`).
- The spec, the skill and four errors' help no longer contradict what lughac does, from a reader's review:
  - the spec: an `independent` scope prints a panic as ``task `name` panicked: …``; `select` picks the same way on every run only on one worker thread; an actor's stack overflow unwinds and fails its scope; a `Ref` in an actor's field is E0475;
  - the skill: only `close` closes a channel; a `mut` parameter changes the caller's variable; `Clock` has `local_offset`;
  - help text: E0429 no longer offers the removed `exit(…)`; E0452 points at `impl I for T`, not a type's own methods; E0313 for a name another module only imports says to make that import `public`; E0404 for arithmetic on a `Ref` points at `r.get()`.
- Long chains of values are freed without recursion (milestone 239, PRP-271): freeing an object called its visit, which freed the next object from inside it, so letting go of a list a million nodes deep nested a million calls. On a small address space (`prlimit --as`, where task stacks shrink to 1 MiB) it ended the program with a segfault and no output, and a recursive walk's `stack overflow` panic segfaulted while unwinding instead of exiting 101; without a limit the same programs ran. An object freed while its worker is already freeing is now queued and freed by the outermost call, as marking already did. Found by lugha-dev's course, whose sandbox runs programs under a 256 MiB limit.
- W0108 is narrowed to where `==` compares more than one thing (a struct of two or more fields, or an enum with a payload): a one-field struct (`Box<T> { v: T }`) or an enum whose variants carry nothing (ordered by a rank) beside a hand-written `Ord` were warned of, though their `==` and `cmp` agree.
- The spec's text caught up with v18, from the v18 spec review and five readers' notes: §1 describes v18's goals instead of v0's "weekend project"; the "Changes since v17" list runs in milestone order and the 6.5 KB "Breaking" paragraph is a list; the §3 grammar has actors, extern unions, `blocking`, `pinned`, the callback words, `scope … pinned` and default type parameters, and the garbled `Set {` line is gone; bare `spawn` is described as E0474; the contextual words are listed in one place; the panic, `defer`, discarded-value, callback, ABI, `as` and handle-printing text match v18; §11's out-of-scope list names only what isn't built, and milestone 121 has its row; eight §12 questions are marked settled. §10's Money example pads cents (`$5.05`, not `$5.5`), unused `Result`s are `let _`, and new notes cover closures capturing values, `spawn` taking the call, why an integer `round`s to a float, and `debug(x)` (a new example, run at `-O0` only, which `tests/spec.rs` now supports). Six error pages use `console.println`.
- `for (a, b) of rx`, a loop or `select` arm over a channel of tuples (or of any item no expression's `Option` mentions), crashed the compiler (`enums are declared before lowering`): the `Option<item>` the receiving end gives was never declared for codegen. The checker now records it for every channel type the program uses. Found writing the skill's examples.
- A closure passed where a function interface is expected (`http.serve(net, addr, fun(req) = …)`, whose `Handler` is `fun(Request): Response + Sendable`) didn't take its parameter types from it (E0412). It now does, as from a function type, and a generic function interface (`interface Pair<T>: fun(T, T): T`) is checked at its arguments when a function converts to it.
- Closing a socket woke none of the tasks waiting on it: a `Listener`'s `accept`, a `Conn`'s `read` or `write`, or a `Udp`'s `recv_from`/`send_to` in another task waited for ever, since closing the descriptor takes it out of the `epoll` set, and a program whose server task waited in `accept` never ended. `close` now wakes each task parked on that socket with `Err("closed")` before closing it, under the runtime's lock (a list of parked socket waits in `net.c`), and a woken task never touches the descriptor again, whose number may already be reused. Found writing the skill's network page.
- A spawned call couldn't take a function as a `Sendable` interface: `s.spawn(http.serve(net, addr, handle))` was E0475 ("a function value, which may have captured anything"), though converting `handle` to `Handler` had already checked its captures. An argument converted to an interface that requires `Sendable` is no longer judged again by its own function type, and a failed conversion is reported once. E0475's message for a capture now reads "its capture `r` is a `Ref<i64>`" instead of quoting the path.
- `console.println(largest(xs).unwrap())` was E0451 (`Display` doesn't meet `Ord`): the expected `Display` reached the receiver of `unwrap`/`expect` and made a generic call's `T` the interface. An expected interface now converts the unwrapped value afterwards, as it already did for a call's own result. Found writing the Lugha skill.
- A program could crash with a segmentation fault (exit 139 instead of 101) when it ended while a task on another worker was still running: the end of `main` freed the other threads' tasks under them (now only under `LUGHA_RC_REPORT`, whose count is what that was for), and `exit` ran OpenSSL's cleanup while a worker was inside OpenSSL (OpenSSL now starts with `OPENSSL_INIT_NO_ATEXIT`). Seen as `tests/tls.rs` crashing; its three tests that connected after one `yield_now`, racing their server task on another worker, now wait until it listens.
- A worker roused just as it became the poller (between parking and saying it polls) waited in `epoll_wait` with work for it: the rouser had bumped the futex word it doesn't wait on, a lost wake-up. Found by PRP-246's stress test, where a pinned task's worker hung about one run in two; it could strand `main` going home before, and was the false deadlock `tests/scheduler_stress.rs`'s `park` case showed under ThreadSanitizer about one run in 100 (none in 600 since) (milestone 214)
- A type written in a signature whose argument must meet a bound given by a block, `S<string>` for `struct S<K: Key>` or `D<i64>` for `D<T: Display>`, was reported as not meeting it: signatures are read before the blocks, so such checks now wait until every block is in, as one in a body always did. A parameter missing a derivable bound there (`Set<U>` with `T: Ord`) is now E0451, naming the bound, as in a body.
- A tuple `let` shadowing an earlier name (`let r = …; let (c, r) = …;`) stored into the earlier variable's slot: it leaked when the types matched and could crash when they didn't. Each name a `let` pattern binds is now a new variable.
- Writing inside a map entry (`m["a"].x = 5`, `n["a"][0] = 3`, `n["a"].push(4)`, `swap(n["a"], …)`, `for x of mut n["a"]`) crashed lughac in codegen; it is now E0502, as for an element a type's `index` returned, with help that copies the entry out and writes it back. `for x of mut g[i]` through `index` is E0502 too. The E0404 help for `m[k] += v` and `a[i] += v` quotes the program's own element and value.

## Language history (v1–v17)

What each version of the language added, and which programs stopped being valid, as the specification recorded it before v18. Moved here from the head of `Language v18 Specification.md`, unchanged; v18's own changes stay in the specification while v18 is in progress.

**v15.** This is v14 plus package layout, operator overloading, the standard library (`std.math`, `std.random`, `std.env`, `std.fs`, `std.process`), copy-on-write arrays, loop ownership, nested `mut self` calls, numbers as `T`, user-defined `Ord`, and format widths in characters (milestones 51–66).

**v16.** This is v15 plus shared boxes (`Ref<T>`), block and doc comments, the editor tooling (`lughac lsp`, `fmt`, `test`, `explain`, `init`) and C interop (linking C libraries, callbacks and handles, strings from C, C structs by value) (milestones 67–90).

**v17.** This is v16 plus green threads, channels and `select`, actors, constants, struct update syntax, variants as functions, derivable interfaces, the standard library's networking, TLS, cryptography, HTTP and JSON, and ARM64 Linux (milestones 91–163).

**Changes in v17 since v16** (milestones 91–163):
- Green threads: `spawn f(x)` runs a call concurrently and gives a `Task<T>` (a plain `Task` for a call that returns nothing) whose `join()` waits for the result. `Chan<T>` carries values between green threads: `Chan.new()` (unbuffered) or `Chan.buffered(n)`, `send`, `recv` (an `Option`, `None` once closed), `try_recv`, `close`, `is`. `select` waits on several channels at once, with an `after(ms)` timeout or a `default` that never waits. `std.task` has `sleep(ms)` and `yield_now()`. Every function stays an ordinary function: there is no `async` and no `await`, so nothing is coloured. All green threads share the program's one OS thread; a panic in any of them ends the program, as does `main` returning, and a deadlock is a panic (sections 2–9).
- Actors: `actor Counter { count: i64, fun add(mut self, n: i64) { … } fun get(self): i64 = … }` declares state and methods together; `spawn Counter { count: 0 }` starts one and gives a handle of type `Counter`. A method call on the handle is a message, handled one at a time: one with a result waits for it, one without is queued. `stop()`, `join(): Option<string>` and `is` are every handle's; a panic ends only its actor (`join` gives the message, callers waiting panic in turn); fields are private, and nothing that may hold a `Ref` crosses an actor's boundary (E0439) (milestone 92; sections 2–9).
- Struct update syntax: `Model { count: m.count + 1, ..m }` takes every field not written from `m` (milestone 93; sections 3, 4, 5).
- Variants as functions: `Msg.Named` is a `fun(string): Msg` when not called, and so are `Some`, `Ok` and `Err` — `input(name, Msg.Named)`, `xs.map(Some)` (milestone 94; sections 4, 9).
- Faster `lughac test`: a package folder's test files are built into one executable instead of one each (milestone 124; section 9).
- Shared names: a method may be named like a field (`p.name` vs `p.name()`) or, with `self`, like a variant, where uses tell them apart; E0310 remains for a function-holding field, an associated function named like a variant, and two methods (milestone 123; section 4).
- Files built into the program (milestone 128; sections 5, 6, 7, 9): `include_bytes("data/logo.png")` is a `u8[]` and `include_str("notes.txt")` a `string` holding the file's contents, read when the program is compiled; constant expressions, so `const LOGO: u8[] = include_bytes("logo.png");` works. The file must be inside the package's folder (E0447, 16 MiB at most); `include_str` needs UTF-8 (E0448).
- Joining arrays: `xs + ys` is a new array of `xs`'s elements then `ys`'s, `xs += ys` and `s += t` join in place of `a = a + b`, and arrays satisfy `Add` (milestone 122; section 4).
- `==` through `Eq` (milestone 144; sections 4, 5, 9): `Eq` is the prelude's derivable interface with `eq` and `hash`; a struct or enum writing both decides its own equality (E0454 for one alone); a type that isn't `Eq` is E0451 with a path at `==` and at `T: Eq`; derive blocks gain `derive.all(a, b, f)`. **Breaking:** a type's existing `eq`/`hash` methods now take part in `==`.
- Hashing is written in Lugha (milestone 143; sections 4, 5): the prelude's derivable `$Hash`, which `Eq` brings with it; derive blocks gain `derive.fold`, `derive.index` and `derive … for handle` with `derive.address`. Fixed: equal sets or maps built in different orders now hash equal, so a `Set<Set<T>>` holds them once.
- Derive blocks (milestone 142; sections 2–6, 9): `derive Show for struct { … }` says, once, how every struct (or enum, tuple, or one type such as `i64` or `T[]`) meets an interface declared in the same module; `derive.fields(…)` and its siblings reach the fields. A type's own method replaces a block's item, so `impl Date { fun to_json(self): json.Value … }` customises its JSON. **Breaking:** a struct or enum with its own `to_json`/`from_json` now has it used by `json.encode`/`decode`, and one of another shape is E0422 where it is encoded. E0451–E0453.
- `json.encode` and `json.decode` are written in Lugha, in derive blocks of `std.$json_value` (milestone 141; section 9): nothing a program can see changes.
- `json.decode(v)` (milestone 140; standard library, section 5): a `json.Value` back into any data type, `DecodeError` naming the path to the first mismatch; `let p: Person = json.decode(v)?;` — `?` now passes the type it is expected to give to its operand, so a generic call's type comes from it.
- `json.encode(x)` (milestone 139; standard library, sections 8, 9): any data type to a `json.Value` with no annotation, the built-in `json.Json` bound, E0450 for what isn't data.
- JSON in `std.http` (milestone 138): `req.json()`, `res.json()`, `post_json(url, v)`, and `http.json(status, v)` taking a `json.Value` instead of text.
- `std.json` (milestone 137; standard library): strict RFC 8259 JSON parsing and writing in Lugha — exact `i64` integers, keys in order, duplicate keys refused, limits for hostile input.
- `net.resolve` and `tls.Options.address` (milestone 121): every address a name resolves to, and a connection to a chosen IP address that still verifies the name (in `std.tls` and `std.http`), against DNS rebinding.
- UDP in `std.net` (milestone 163): `udp_bind`, `udp_bind_shared`, `send_to`, `recv_from`, multicast groups and options, and `interfaces()`.
- HPKE in `std.crypto` (milestone 162): `hpke_seal(public, info, plaintext, aad)` and `hpke_open(secret, info, sealed, aad)`, sealing to an X25519 public key (RFC 9180, base mode, one suite).
- TLS by key (milestone 161; standard library, E0332): `tls.listen_keys`, `tls.connect_keys`, `Conn.peer_key()` and `Listener.set_accept` — mutual TLS 1.3 where each side proves an Ed25519 key from the other's list (raw public keys, RFC 7250), with no certificates. Programs loading `std.tls`, `std.http` or `std.crypto` need OpenSSL 3.2 or newer.
- Sealing and key exchange in `std.crypto` (milestone 160): ChaCha20-Poly1305 (RFC 8439) and X25519 (RFC 7748); `CryptoError` gains `NotAuthentic` and `BadKey`.
- `crypto.hkdf_sha256`: HKDF-SHA256 key derivation, RFC 5869 (milestone 120).
- `http.request_tls_with`: `Limits` and `tls.Options` in one request (milestone 119).
- `and_then` on `Option` and `Result` (milestone 118); a closure whose expected result is only partly known (`Option<U>`) takes its result from its body.
- Octal literals (milestone 117; section 2): `0o600`; a leading zero (`0600`) stays decimal and warns W0107.
- `fs.sync` (milestone 116): `fsync` on a file or folder, so a saved file and its rename survive a power cut.
- Calendar dates and the local offset in `std.time` (milestone 145): `time.civil(ms, offset_s)`, `time.from_civil(c, offset_s)` and `time.local_offset(ms)`, with `Civil` and `TimeError` (standard library).
- File streams in `std.fs` (milestone 146): `fs.open`, `fs.create` and `fs.append` give a `File` to read by line or in chunks and write piece by piece (standard library).
- Constants computed by pure code (milestone 147; sections 6, 8): a `const`'s value may be any expression, calls, `if`, `match`, blocks, closures and interpolation included, as long as nothing it reaches prints, touches files, the operating system or C, or starts tasks, channels or actors (E0445, with the path); constants read inside the functions it calls are computed first (E0446 for a cycle through them). Still computed once before `main`, never while compiling.
- `defer` (milestone 151; sections 2, 3, 5, 6, 9): `defer f.close();`, `defer n += 1;` or `defer { … }` runs when its block is left — its end, `return`, `?`, `break`, `continue` — last first, after a tail or `return` value is computed, reading values as they are then; a panic didn't run it until milestone 194, which unwinds. Leaving a deferred statement is E0455; one with a value is E0456. **Breaking:** `defer` is a keyword.
- `loop` and labels (milestone 152; sections 2, 3, 5, 6, 9): `loop { … }` repeats until a `break`, and is an expression: `let x = loop { … break v; };`. A `loop` no `break` leaves has type `never`, so a function whose only exit is a `return` inside it needs no `panic("unreachable")`. `name:` labels a `loop`, `while` or `for` for `break name;` and `continue name;`. E0512 (unknown label), E0513 (a label reused inside its loop), E0514 (`break` with a value out of `while` or `for`). **Breaking:** `loop` is a keyword.
- `fs.size` (milestone 153; standard library): a regular file's size in bytes from `stat(2)`, links followed, without opening it, so a program can refuse a file too big to read whole.
- Semantic tokens (milestone 154; section 9): `lughac lsp` classifies every token of a file — keywords, strings, numbers, comments, operators, and names by what the check resolved them to — so editors without Lugha's TextMate grammar (Neovim, Helix, Zed) colour it, and VS Code colours names by meaning.
- Indexing your own types (milestone 155; sections 3, 4, 8): `a[i]` on a struct, enum, interface value or bounded `T` calls `fun index(self, i: I): T`, and `a[i] = v` calls `fun set_index(mut self, i: I, v: T)`; `a[x, y]` is `a[(x, y)]` for every type, so maps with tuple keys take `m[x, y]` too.
- Arithmetic between different types (milestones 158–159; sections 4, 8): a type may have one `add`, `sub`, `mul`, `div` and `rem` per right-hand type, chosen by the operand's exact type (`v * w` and `v * 2.0`), and `impl f64 { fun mul(self, v: V): V }` beside `V` makes `2.0 * v`; E0457, E0458.
- `for x of mut g[i]`, `swap(g[i], b)` and `out g[i]` through a type's `index` (milestone 157; sections 4, 8): each works on a copy of the element, handed back to `set_index`; the loop hands it back on every way out but a panic.
- Read-modify-write through `[ ]` (milestone 156; sections 4, 5, 8): a map's entry is a place, changed where it is (`m[k] += 1`, `m[k].x = v`, `m[k].push(x)`, `swap(m[a], m[b])`, `for x of mut m[k]`), and a missing key panics as a read does; `g[i] += v`, `g[i].x = v`, `g[i][j] = v` and `g[i].push(x)` on a type read the element with `index`, change the copy and hand it back with `set_index`.
- An iterator chain's expected type reaches `map`'s closure through `collect` and the helpers between (milestone 150; section 5): `let n: Option<i64>[] = xs.iter().map(fun(x) = None).collect();`.
- Handing over arguments (milestone 149; sections 4, 9): `x = f(x)`, where `f` keeps its parameter, no longer copies `x`'s arrays on every call; a function that stores a parameter on its last use takes it without a copy from a caller that is done with it (quadratic loops become linear). Programs print the same.
- A generic call only its result can type takes its type through a method whose result mentions the receiver's type parameters (milestone 148; sections 4, 5): `let p: Person = json.decode(v).unwrap();`, `.expect(…)`, and a program's own methods (`let n: u8 = zeros().first();`).
- Keeping data on disk (milestone 115): `fs.rename` (atomic within a file system), `fs.set_mode` (`chmod`), the `flush()` built-in, and `std.time` (`now_ms`, `monotonic_ms`).
- `std.toml` (milestone 114; standard library): a read-only TOML 1.0 parser in Lugha with limits for hostile input; the prelude's `xs.join(sep)` is linear (it was quadratic).
- `std.crypto` (milestone 113; standard library): SHA-256 (one-shot and streamed), Ed25519 keys, signing and verifying, secure random bytes and constant-time comparison, over the system's OpenSSL 3.
- TLS (milestone 112; standard library, E0332): `std.tls` over the system's OpenSSL 3 with always-on verification, and `https://` in `std.http` (`serve_tls`, `request_tls`).
- `std.http` (milestone 111; standard library): an HTTP/1.1 server with strict limits and a client, in Lugha over `std.net`; a literal `if` branch takes a typed sibling's type (`if c { b - 1 } else { 255 }` with `b: u8`).
- `std.net` (milestone 110; sections 7, standard library): TCP listeners and connections whose waits pause only their green thread, through `epoll`; timeouts; UDP since milestone 163.
- Global constants (milestone 109; sections 2, 3, 6, 8): `[private | public] const NAME: T = value;` — constant expressions only (E0445; any pure expression since milestone 147), in any order without cycles (E0446), evaluated once before `main`; no mutable statics. `const` is a keyword.
- A float's raw bits (milestone 108; section 4): `x.to_bits()` (`f64` → `u64`, `f32` → `u32`) and `f64.from_bits(b)` / `f32.from_bits(b)`, exactly the IEEE 754 bits.
- The unit type `()` replaces `void` (milestone 107; sections 3, 4, 6): a type and its one value, held anywhere a value is (`Result<(), E>`, `Chan<()>`); E0407 is retired; W0106 warns on `let x = log();`.
- Extern structs hold `Option` of a handle (C's nullable pointer); unions hold plain data only, so no pointer is made up from a number (milestone 106; section 8).
- The C boundary takes pointers (milestones 103–105; section 8): `ptr` and `mut` parameters; arrays as `xs: T[]` and `mut xs: T[]`; `extern union`; `CPtr` with `c_read`/`c_write`; callbacks taking `T[]` and `Ref<T[]>`.
- `out` parameters on externs: `extern fun get_fuel(c: Context, out fuel: u64): bool;` and `get_fuel(ctx, out fuel)` — C writes through the pointer and the place gets the value after the call (milestone 102; sections 3, 8).
- Maps and sets: `Map<K, V>` and `Set<T>`, built in, with `#{"ann": 31}` and `#{1, 2}` literals (`Map { … }` and `Set { … }` since v18); values like arrays, keys any `Eq` type without floats, insertion order, `m[k]`, `for (k, v) of m`, `==` regardless of order. The iterator type `it.map(f)` returns is renamed `Mapped` (milestone 101; sections 2–5, 9, 10).
- Glob re-exports: `public import raw { * };` makes every `public` item of `raw` an item of this module, so a package's entry can flatten a sub-module (milestone 100; sections 3, 6).
- Package entry modules: `import kivuli;` imports the package's `lib.la` (in its `source` folder) as the module `kivuli`; `lughac init --lib` writes one (milestone 99; sections 6, 9).
- Module doc comments: a `/** … */` at the top of a file, followed by a blank line or an `import`, documents its module; hovering the module's name shows it, and the std modules are documented (milestone 98; sections 2, 9).
- `pkg-config --cflags` may give `-mfpmath=sse`, `-msse` and `-msse2`, so a package can list C files alongside GTK (section 8).
- `lughac fmt` hugs a call's trailing array or struct literal (`column([` … `])`) and keeps a function's header whole while its body breaks (milestone 95; section 9).
- A generic call only its result can type takes its type from its siblings: `assert_eq(text("hi"), expected)`, `text("hi") == expected` (milestone 96; section 4).
- Packages and tests: `lughac test` and `lughac check` on a file in a package's `source` folder build it as that package's module (`glow.diff`), so modules importing each other can be tested, and its tests are named `glow.diff.name`; programs in a package's `test/`, `tests/` and `examples/` see its package-level items; `lughac check` takes a file without `main` as a library; `lugha.lock` sits beside the governing `lugha.toml`; and `skip(reason)` reports a test skipped (milestone 97; sections 6, 9).
- `lughac init` writes a `test/` folder with one passing test, and a program's greeting in its own module, `src/greeting.la` (milestone 129; section 9).
- Executables run on any x86-64 CPU: lughac builds for the baseline `x86-64` level, and `--cpu=x86-64-v2|x86-64-v3|x86-64-v4|native` on `build`, `run` and `test` chooses a newer level or this machine's own CPU (milestone 130; section 9).
- The collector is built into lughac: bdwgc 8.2.12 is compiled once from embedded source and linked into every program statically, so neither lughac nor its programs need the system's `libgc` (milestone 131; sections 7, 9). Removed in milestone 193.
- `$LUGHA_CC` chooses the C compiler: `LUGHA_CC=clang` or `LUGHA_CC="zig cc"` (a program and its first arguments, split on spaces, never run by a shell) compiles the runtime and `[link]` C files and links; unset or blank is `cc` (milestone 132; section 9).
- Linux on ARM64: `lughac build --target aarch64-unknown-linux-gnu` writes an ARM64 executable (green threads and actors included), compiled and linked with `aarch64-linux-gnu-gcc` unless `$LUGHA_CC` names another; extern structs cross to C by value there as AAPCS64 passes them (milestones 133–134; sections 8, 9).
- Output lughac couldn't write is exit 2 (section 9): `lughac build --emit=ir > out.ll` on a full disk no longer exits 0. A reader that stops early is not a failure.

Every valid v16 program is a valid v17 one, unless it uses `spawn`, `select`, `actor` or `const` as a name (keywords now), or declares a function named `skip` (an intrinsic since milestone 97, E0302), `flush` (one since milestone 115) or `include_bytes`/`include_str` (since milestone 128), or names the iterator type `Map` (now `Mapped`, milestone 101; a program's own `Map` is fine). A module's own `Task` or `Chan` still means its own, as for `Ref`. Within v17, a `tls.Options { … }` literal naming every field without `..base` needs `address` since milestone 121 (`..tls.options()` keeps it short).

**Changes in v16 since v15** (milestones 67–90):
- Shared boxes: `Ref<T>` is the one value that copies share. `Ref.new(v)`, `r.get()` (a copy), `r.set(v)`, `r.update(f)` and `r.is(s)` are its whole API. A closure may update a box it captured, and linked data can point at itself. Boxes aren't `Eq`, and print as `Ref(…)` when they cycle (sections 4, 7, 9).
- `env.set_current_dir(path)` changes the program's working directory; relative paths and programs started afterwards follow it (milestone 68; "The standard library").
- `lughac init [folder] [--lib] [--name N]` starts a program, or a library with an example, in a folder; it never overwrites a file (milestone 69; section 9).
- `lughac lsp` is a language server: editors get `lughac check`'s diagnostics as you type, for unsaved text too (milestone 70; section 9), and hovering shows the type of an expression or a declared name, also while the program has errors (milestone 71); Go to Definition jumps from a name to its declaration (milestone 72); completion offers members after `.` and the names in scope (milestone 73); signature help shows the call being typed with its current parameter (milestone 74); and all of these keep working in a file with a syntax error, which the server checks partially (milestone 75).
- Block comments: `/* … */`, over any number of lines, nesting, wherever whitespace may be; an unclosed one is E0113 (milestone 76; section 2).
- Doc comments: a `/** … */` right before a declaration documents it, in Markdown with `@param` and `@returns`; the compiler ignores it, the language server shows it, and std and the prelude are documented (milestone 77; sections 2, 9).
- Snippets in the editor: completion inserts calls with a placeholder per parameter, and `value.match` writes out every variant (milestone 78; section 9).
- Quick fixes in the editor: a non-exhaustive `match` (E0417) offers to add every missing arm, or a `_` arm (milestone 79; section 9).
- `lughac fmt [paths…] [--check]` rewrites `.la` files in one canonical style, keeping every comment, and checks its own output before writing (milestone 80; section 9).
- Formatting in the editor: the language server answers Format Document with the same formatter, for unsaved text too (milestone 81; section 9).
- More quick fixes: `let mut` for an assignment to an immutable `let` (E0501), the closest variant for a misspelled one (W0103), a std import for `math.`-style names (E0301) (milestone 82; section 9).
- Find References and Rename in the editor, across the checked files; a rename is checked before it is offered (milestone 83; section 9).
- `lughac test`: `@test` functions (`@` starts an attribute), `assert`, `assert_eq` and `assert_ne`, each test run in its own process, in parallel, with a time limit (milestone 84; sections 2, 3, 5, 9).
- Tests in the editor: `lughac test --list`, `--json` and `--exact` for tools, and VS Code's Testing view with a ▶ beside each test, never in untrusted folders (milestone 85; section 9).
- `lughac explain CODE` explains every error and warning code, diagnostics end with a line pointing to it, and the editor links each code to its explanation (milestone 86; section 9).
- Linking C libraries: a `[link]` table in `lugha.toml` names libraries, library folders, header folders, C files to compile and `pkg-config` packages; the tables of every package a program uses apply (milestone 87; sections 6, 8, 9).
- Callbacks and handles: `extern type Name;` declares an opaque C pointer type; a function type in an extern's parameters is a callback C can call, named functions anywhere and closures through user data (`data`, `release`); `extern "symbol" fun name(…)` gives a C function a Lugha name of its own (milestone 88; sections 3, 4, 7, 8, 9).
- Strings from C: an extern may return `string` or `Option<string>` and take `Option<string>`, and a callback may receive them; C's text is copied, with invalid UTF-8 replaced by U+FFFD (milestone 89; section 8).
- C structs by value: `extern struct Name { … }` has C's layout and goes to and from C (externs and callbacks) by value, exactly as C passes it on x86-64 (milestone 90; sections 3, 4, 8, 9).

Every valid v15 program is a valid v16 one, unless it uses `Ref` as the name of something other than a type (a module's own type `Ref` still means its own), or declares a function named `assert`, `assert_eq` or `assert_ne`, which are intrinsics since milestone 84 (E0302).

**v14.** This is v13 plus binary I/O, `char`, tuples, `format`, import aliases and whole-module re-exports, and git packages (milestones 45–50).

**Changes in v15 since v14** (milestones 51–66):
- A package's `[package]` table may give its `name`, checked against the key a manifest lists it under (E0327), and its `source`, the folder its modules start in: with `source = "src"`, `src/array.la` of package `glowworm` is `glowworm.array` (section 6).
- A program with no `lugha.toml` beside its main file uses the nearest one above it, looking no further than a folder with `.git` or the home folder; when that manifest names a package, the program imports it by that name, so `glowworm/examples/basics.la` writes `import glowworm.array;` with no manifest of its own (section 6).
- A file imported as two modules is E0328 (section 6).
- A manifest path such as `".."` resolves when the main file is given with a folder (`lughac run example/main.la`); v14 reported E0322.
- Operator overloading: `a + b` on a struct, enum or interface value calls `a.add(b)`, and likewise `-` `sub`, `*` `mul`, `/` `div`, `%` `rem` and unary `-` `neg`, for a method of the operator's shape; `a += b` is `a = a.add(b)`. The prelude's `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg` and `Num` are bounds that the numbers (and `string`, for `Add`) satisfy, so `fun add<T: Add>(a: T, b: T): T = a + b;` works for numbers, strings and your own types; `0` and `1` are values of a `T: Num`. An `impl` block may bound its parameters, `impl<T: Num> Grid<T> { … }` (sections 3–5).
- A standard library: `import std.math;` loads a module bundled with `lughac`, only when imported. `std.math` has `sqrt`, `pow`, `exp`, `ln`, `log10`, `sin`, `cos`, `tan`, `atan2`, `floor`, `ceil` and `round` for any `T: Float` (`f32` or `f64`, a new prelude bound), `abs`, `min`, `max` and `clamp`, and `pi()` and `e()`. `std` is a reserved package name (sections 4, 6, "The standard library").
- Arrays are copy-on-write: a copy shares the array until either side writes to it, so copying costs a constant time and reading a copy never copies. Every copy still behaves as an independent value, and no program's output changes (sections 4, 5, 7, 9, 12). A loop makes the arrays it writes, and can't share, unique once before it starts, so its writes cost no more than before copy-on-write (milestone 56; section 9).
- An argument of a `mut self` call may call methods on the receiver, `g.tanh(g.add(a, b))`, or read numbers and strings from it; only an argument that can be the receiver's own storage (`v.add(v)`, `v.add(v.inner)`) is E0508. The arguments run before the receiver is reached, and a change they make to a struct containing the receiver is no longer E0510 unless an array index lies between (milestone 57; sections 4–5).
- Numbers as `T`: `n as T` and `x as f64` cast to and from a type parameter bounded by `Num` or `Float`, and any integer literal is a `T: Num` and any float literal a `T: Float` (`x * 2`, `x * 0.5`); a literal that doesn't fit an instance's type is E0402, naming the instance (milestone 58; section 4).
- User-defined order: a struct or enum with `fun cmp(self, other: Self): Ordering`, the prelude's new `enum Ordering { Less, Equal, Greater }` (written `Ordering.Less`), is `Ord`: `<`, `<=`, `>` and `>=` call `cmp`, tuples compare through it, and `math.min`, `it.min()` and the new `xs.sort()` accept it. `==` stays structural (milestone 59; section 4).
- An imported std module's functions and methods are compiled only when the program reaches them, as the prelude's are; every one is still checked. No program's behaviour changes, only the size of its IR (milestone 60; sections 6, 9).
- `it.sum()` goes through one generic prelude helper for every numeric type; nothing visible changes (milestone 61; section 9).
- `parse_i64`, `parse_u64` and `string_from_utf8` are written in Lugha in the prelude, and `string_from_utf8` and `s.chars()` share one UTF-8 decoder; results and messages are unchanged (milestone 62; section 9).
- A format width counts characters, not bytes (`{"Zoë":<6}` pads with three spaces, not two), and any character may fill (`{n:é^9}`); text without non-ASCII characters prints as before (milestone 63; section 5).
- `std.env`: `env.get(name)` reads an environment variable as an `Option<string>`, and `env.current_dir()` gives the working directory; nothing sets either (milestone 64; "The standard library").
- `std.fs`: `fs.list_dir`, `make_dir`, `make_dirs`, `remove_file`, `remove_dir` (empty folders only), `exists`, `is_dir` and `is_file` (milestone 65; "The standard library").
- `std.process`: `process.run`, `run_with` and `call` run another program with an argument list, never through a shell, and give its exit code and output (milestone 66; "The standard library").
- `std.random`: `random.seeded(42)` or `random.from_os()` makes a generator (xoshiro256\*\*, not cryptographically secure) with `uniform`, `below`, `between`, `normal`, `chance`, `choice` and `shuffle` ("The standard library").

Every valid v14 program and package is a valid v15 one: a module's own type or interface named `Add`, `Sub`, `Mul`, `Div`, `Rem`, `Neg`, `Num` or `Ordering` still means its own, as for `Iter`.

**Changes in v14 since v13** (milestones 45–50):

**v13.** This is v12 plus `Self` in declarations, `for … of mut`, more iterator helpers and format specifiers (milestones 41–44).

- Binary I/O: `read_bytes`, `write_bytes`, `append_bytes`, `read_stdin_bytes`; `s.to_bytes()`; `string_from_utf8(bytes)`, which rejects invalid UTF-8. An index may be of any integer type (sections 4–5).
- `char`, a Unicode scalar value: `'a'`, `'é'`, `'\u{1F600}'`; `s.chars()` and `s.char_count()`; `c as u32`, `n as char`, `char_from(n)`; classification and case for ASCII and Latin-1 (sections 2–5).
- Tuples: `(A, B)` types and `(a, b)` values, `t.0`, patterns `(p, q)` in `match`, `if let`, `let (a, b) = t;` and `for (i, w) of …`; element-wise `==`, lexicographic `<`, printed `(1, "a")`. `zip` yields tuples, and `Pair` is gone (sections 3–5).
- `format("{} has {:>4} items", name, n)` returns a `string`: a literal template whose holes `{}` and `{:spec}` take the further arguments in order (E0432; sections 2, 5).
- Imports take `as`: `import a.util as u1;` binds the module as `u1`, and `import a.b { X as Y };` binds the item as `Y`. `public import a.b [as v];` re-exports the whole module, which files importing this one reach as `m.v.X` (sections 3, 6).
- Git packages: a manifest entry `name = { git = "https://…", version = "1.2" }` fetches the newest matching `vX.Y.Z` tag with the system `git` into a per-user cache, and `lugha.lock` pins its commit; `lughac update` re-resolves, and `--offline` never runs `git` (E0325, E0326; sections 6, 9).

A valid v13 program is a valid v14 program unless it uses `Pair` or `zip`'s `Pair` fields (`zip` yields tuples now: `p.first` is `p.0`), uses `char` as a name (a type keyword now), or declares a function named `format`, `read_bytes`, `write_bytes`, `append_bytes`, `read_stdin_bytes` or `string_from_utf8`, which are now intrinsics.

**v12.** This is v11 plus printing any value: the prelude's `Display` and `show`, built-in forms, and `unwrap on Err: <error>` (milestones 39–40).

**Changes in v13 since v12** (milestones 41–44):
- In a struct's fields and an enum's payloads, `Self` is the type being declared: `struct Tree<T> { value: T, kids: Self[] }`, `enum List { Cons(i64, Self), Nil }` (section 4).
- `for x of mut xs` makes `x` each element itself, so `x *= 2` changes `xs`; `for x of mut it` advances the iterator `it` itself, so a later loop resumes where a `break` left it (sections 3, 5).
- Iterators gain `zip` (yielding the prelude's `Pair { first, second }` in v13; a tuple since v14), `chain`, `take_while`, `skip_while`, `flat_map`, `min`, `max` and `position` (section 4).
- An interpolation may end in a format specifier: `"{pi:.2}"`, `"{n:>6}"`, `"{n:05}"`, `"{n:#x}"`, `"{name:*^9}"`; a bad one is E0431 (sections 3, 5).

Every valid v12 program was a valid v13 program.

**v11.** This is v10 plus package versions and named imports and re-exports (milestones 37–38).

**Changes in v12 since v11** (milestones 39–40):
- `print`, `println`, `eprint`, `eprintln`, `to_string` and `"{x}"` accept structs, enums, arrays, `Option`, `Result` and type parameters. A type with its own `fun show(self): string` (the prelude's `Display`) prints through it; any other prints in a built-in form, `Point { x: 1, y: 2 }`, `Circle(1.5)`, `[Some(1), None]`, with the strings inside it quoted (sections 4–6).
- Interface values print as the value inside them, function values as `<fun>`, and `unwrap()` on an `Err` panics with `unwrap on Err: ` followed by the error (sections 4–5).

Every valid v11 program was a valid v12 program; only the `unwrap on Err` panic message is longer.

**v10.** This is v9 plus `Self` in `impl` blocks, default methods on concrete types, `i8`/`i16`/`u16` with checked, saturating and rotating methods, and iterator helpers (milestones 34–36).

**Changes in v11 since v10** (milestones 37–38):
- A package's `lugha.toml` may declare its version, `[package]` then `version = "1.4.0"`, and a manifest may require a compatible one, `geo = { path = "libs/geo", version = "1.2" }`; a version that doesn't meet it is E0324 (section 6).
- `import a.b { X, y };` brings items into a file by name, and `public import a.b { X, y };` re-exports them as items of the module, so a program can use `shapes.Vec2` from a package it doesn't list (sections 3, 6).

Every valid v10 program and manifest was valid in v11.

**v9.** This is v8 plus or-patterns, `mut` bindings, `unwrap`/`expect`, `%=`, and `if let`, `while let` and `let … else` (milestones 31–33).

**Changes in v10 since v9** (milestones 34–36):
- Inside `impl T`, `Self` is `T` (with its parameters, `Stack<T>`), as a type, in struct literals (`Self { x: 0 }`), associated calls (`Self.new()`) and variants (`Self.Red`) (section 4).
- A default method can be called on a struct or enum that lacks its own, `c.describe()`, when exactly one visible interface the type satisfies supplies it; two are E0430 (section 4).
- `i8`, `i16` and `u16` are integer types like the others. Every integer type has `checked_add/sub/mul/div` (an `Option`), `saturating_add/sub/mul` and `rotate_left/right`, and the constants `I.MIN` and `I.MAX` (`i16.MAX`); `parse_u64(s)` parses a `u64` (sections 2–5, 8).
- Iterator helpers: `xs.iter()`, `s.bytes()` and `range(a, b)` make iterators; `it.map(f)`, `filter`, `take`, `skip` and `enumerate` wrap one lazily, and `collect`, `count`, `fold`, `any`, `all`, `find` and `sum` consume it. `for b of s` loops over a string's bytes (sections 4–5).

A valid v9 program was a valid v10 program unless it uses `i8`, `i16` or `u16` as a name, which are type keywords now, or declares a function named `parse_u64`, which is now an intrinsic.

**v8.** This is v7 plus packages: a `lugha.toml` manifest, package imports, and `public` / package / `private` visibility (milestone 30).

**Changes in v9 since v8** (milestones 31–33):
- A pattern may be alternatives, `Circle(r) | Square(r) => r * 2.0` or `"q" | "quit" => …`, nested anywhere; every alternative binds the same names at the same types (E0428). `mut name` makes a binding the arm's own copy, which the arm may change (sections 3–4).
- `o.unwrap()` and `o.expect(msg)` on `Option` and `Result` give the value inside or panic at the call (`unwrap on None`, `unwrap on Err`, or `msg`); `x %= y` is the compound remainder (sections 2–5).
- `if let p = e { … } else { … }`, `while let p = e { … }` and `let p = e else { … };` test one pattern without a full `match`; a `let … else` block must leave (E0429) (sections 3, 5).

Every valid v8 program was a valid v9 program.

**v7.** This is v6 plus `u32`, `u64` and `f32`, bit operators, and wrapping and bit-counting methods on integers (milestones 27–29).

**Changes in v8 since v7** (milestone 30):
- A `lugha.toml` next to the main file lists packages, `name = "path"` under `[packages]`; `import geo.shapes;` then loads `shapes.la` from package `geo`'s folder, and a package may list its own packages in its own `lugha.toml` (section 6).
- `public` is allowed (it was reserved, E0317): an item without a keyword is now visible within its own package, `public` makes it visible to other packages, and `private` still limits it to its module. A `public` declaration may mention only `public` types (sections 3, 6).

Every valid v7 program was a valid v8 program: one without a `lugha.toml` is a single package, where the default visibility still reaches every module.

**v6.** This is v5 plus generic interfaces, iterators, `Self` in interfaces and converting between interfaces (milestones 23–26).

**Changes in v7 since v6** (milestones 27–29):
- `u32`, `u64` and `f32` are numeric types: literals take them from context, arithmetic and overflow panics work at their widths, every numeric type casts to every other, and they print, interpolate and cross the C boundary (sections 2, 4, 5, 7–9).
- Bit operators `&`, `|`, `^`, `~`, `<<` and `>>` on integers, with Rust's precedence (`flags & MASK == 0` is `(flags & MASK) == 0`), the compound forms `&=` `|=` `^=` `<<=` `>>=`, binary literals (`0b1010`), and a panic for a shift that is negative or at least the type's width (sections 2–5, 9).
- Every integer type has `wrapping_add`, `wrapping_sub` and `wrapping_mul`, which never panic, and `count_ones`, `leading_zeros` and `trailing_zeros`, which give an `i64` (sections 4, 9).

A valid v6 program was a valid v7 program unless it used `u32`, `u64` or `f32` as a name: they are type keywords now, like `i32`.

**v5.** This is v4 plus interface values, type patterns, default methods and `?` converting into an interface error (milestones 20–22).

**Changes in v6 since v5** (milestones 23–26):
- An interface may take type parameters, and a bound passes it arguments: `interface Source<T> { fun next(mut self): Option<T>; }`, `fun collect<T, S: Source<T>>(src: S): T[]`. A parameter that appears only in a bound's arguments is read off the concrete type's methods. A generic interface is a type too: `let s: Source<i64> = Count { n: 0, end: 3 };` (sections 3–4, 9).
- The prelude declares `interface Iter<T> { fun next(mut self): Option<T>; }`, and `for x of e` loops over anything with that `next`, working on a copy of `e` (sections 4–5, 9).
- Inside an interface, `Self` is the type that satisfies it: `fun less(self, other: Self): bool`. Such an interface is a bound only; as a type it is E0427 (sections 4, 9).
- A value of one interface type converts to another where that one is expected, when its interface declares every item of the other: a `Pet` becomes a `Named`, and `?` converts interface errors the same way (sections 4, 7, 9).

Every valid v5 program was a valid v6 program.

**v4.** This is v3 plus `Result` and `?`, string and `Option`/`Result` helpers, and input and output (milestones 17–19); v4.1 allows string literals inside interpolations.

**Changes in v5 since v4** (milestones 20–22):
- An interface whose items are all methods is a type: `let shapes: Shape[] = [c, sq];`. A value converts to it where an interface is expected, and a call on it runs the concrete type's method (sections 4, 7, 9).
- A type pattern, `c: Circle => …` in a `match` on an interface value, matches when the value holds that type and binds it (sections 3–4).
- An interface method may have a default body, which a type gets unless it has the method itself (sections 3–4, 9).
- `?` converts an error into an interface error: in a function returning `Result<U, Error>`, `?` on a `Result<T, ParseError>` wraps the `ParseError` as an `Error` (section 4).

Every valid v4 program was a valid v5 program.

**v3.** This is v2 plus command-line arguments and number parsing, string interpolation, functions as values, closures, and array helpers (milestones 13–16).

**Changes in v4 since v3** (milestones 17–19):
- `Result<T, E>` is predeclared, with `Ok(x)` and `Err(e)` written without a prefix (section 4).
- The postfix `?` gives a `Result`'s `Ok` value or an `Option`'s `Some` value, or returns the failure from the function at once (sections 2–4).
- Strings have `lines`, `split`, `trim`, `contains`, `starts_with`, `ends_with` and `slice`, `string[]` has `join`, and `Option` and `Result` have `unwrap_or`, `ok_or`, `ok`, `map`, `map_err` and `is_*` (section 4).
