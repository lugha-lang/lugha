# E0439: An actor used against its rules

An actor's state belongs to its own green thread. Outside the actor you
hold a handle: you start the actor in a scope, `s.spawn(Counter { … })`,
and reach it only through its methods, which are messages. So its fields
can't be read or written from outside:

```lugha
actor Counter {
    count: i64,
    fun get(self): i64 = self.count;
}

fun main(console: Console, root: Scope) {
    let c = root.spawn(Counter { count: 0 });
    console.println(c.count); // error: E0439
}
```

Ask the actor instead:

```lugha
actor Counter {
    count: i64,
    fun get(self): i64 = self.count;
}

fun main(console: Console, root: Scope) {
    let c = root.spawn(Counter { count: 0 });
    console.println(c.get());
}
```

The state exists only inside the actor, so a literal of it (or an
associated function returning it) may appear only where it is spawned:

```lugha
actor Counter {
    count: i64,
}

fun main() {
    let state = Counter { count: 0 }; // error: E0439
}
```

Write `let c = root.spawn(Counter { count: 0 });`, in a scope or with the
root scope `main` takes.

What crosses an actor's boundary — its fields, its methods' parameters and
results — must be sendable, as everything crossing to another task must:
a `Ref` there is E0475.

An actor can't have type parameters, nor can its methods, and it can't
declare a method named `stop` or `is`: every handle has those.

A mailbox holds a number of messages written as a positive literal,
`actor Log mailbox 10_000 { … }`; anything else is this error too:

```lugha
actor Log mailbox 0 { // error: E0439
    lines: string[],
}

fun main() {}
```

Leave it out for the default, 1,024 messages, or give the number:

```lugha
actor Log mailbox 100 {
    lines: string[],
}

fun main() {}
```
