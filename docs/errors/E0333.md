# E0333: A package declares C code without the `ffi` permission

C code can do anything the process can: read any file, open any socket,
start any program. Capabilities only mean something if a package can't
reach the world without being handed one, so a package may declare C
code — an `extern fun`, an `extern type`, or a `[link]` table of C
libraries and files — only when the program trusts it. The program says
so in its own `lugha.toml`, with `allow = ["ffi"]` on the package's entry.

A grant covers the package and everything it depends on. `lugha.lock`
names every package that may run C code and the grant that lets it, and
`lughac update` prints a line when an update gives one more package that
reach. The program's own code, and the bundled prelude and standard
library, never need a grant.

The example is a manifest and a package, so it isn't checked as one:

```text
# lugha.toml of the program
[packages]
sqlite = { path = "../sqlite" }

// ../sqlite/src/lib.la
extern fun sqlite3_libversion_number(): i32; // error: E0333
```

Grant it, if you trust it:

```text
[packages]
sqlite = { path = "../sqlite", allow = ["ffi"] }
```

Reading C's memory needs the same trust. `p.view(n, f)` gives a view of
`n` elements at `p`, and nothing can check `n` against what C allocated,
so a package handed a `CPtr` could read or write anywhere. Outside the
program's own code, `p.view` needs the grant too:

```text
// ../report/src/lib.la, a package the program doesn't grant
public fun peek(p: CPtr): u8 = p.view(1, fun(v: View<u8>) = v[0]); // error: E0333
```

Holding or passing a `CPtr`, and taking or indexing a view someone else
made, need no grant: a view's bounds were set by code the program trusts.

The help names the entry to change: the package's own when the program
lists it, or else the program's dependency that brings it in. Only the
program's `lugha.toml` grants: `allow` in a package's own manifest is
E0321.
