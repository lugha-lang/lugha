# E0336: The OpenSSL named for a target isn't one

A build for another platform of a program loading `std.tls`, `std.http`
or `std.crypto` links the OpenSSL named by `LUGHA_OPENSSL_<TARGET>` (the
target in capitals, `-` written `_`; see E0334). The variable is set, but
what it names can't be that OpenSSL: the path isn't absolute, isn't a
folder, or the folder lacks one of the files a build links.

```text
LUGHA_OPENSSL_AARCH64_APPLE_DARWIN=openssl-mac lughac build app.la --target=aarch64-apple-darwin
// error: E0336: `openssl-mac` isn't an absolute path
```

The folder must be an absolute path holding, built for the target:

- `include/openssl/ssl.h`, OpenSSL's headers;
- `lib/libssl.a` and `lib/libcrypto.a`, its static libraries.

An OpenSSL installed with `make install_dev` into a fresh `--prefix`
looks like this. A folder holding only shared libraries (`.so`, `.dylib`)
won't do: they would have to be installed where the program runs.

Unset the variable to build without TLS or crypto support for that
target (E0334), or build without `--target`.
