# E0459: An `impl I for T` written where it may not be

A type implements an interface through an `impl I for T { … }` block, and
that block has a fixed home: the module that declares the interface, or the
module that declares the type. So no two packages can give one type two
implementations of one interface. The block must also be for a struct, an
enum, an actor or an extern type, and name an interface that types
implement this way: the prelude's `Eq`, `Ord`, `Iter`, `Display` and the
operator interfaces, indexing's `index` and `set_index`, and derivable
interfaces such as `json.Json` are still met by their methods' names.

```lugha
interface Shape {
    fun area(self): f64;
}

impl Shape for f64 { // error: E0459
    fun area(self): f64 = self * self;
}

fun main() {}
```

A number can't implement an interface of a program's yet. Wrap it in a
type of your own:

```lugha
interface Shape {
    fun area(self): f64;
}

struct Square { side: f64 }

impl Shape for Square {
    fun area(self): f64 = self.side * self.side;
}

fun main() {
    let s: Shape = Square { side: 2.0 };
    println(s.area());
}
```

The same error comes from a block in a third module. Here `main.la`
declares neither `Shape` nor `Square`:

```text
import geo;
import shapes;

impl shapes.Shape for geo.Square { // error: E0459
    fun area(self): f64 = self.side * self.side;
}
```

Move the block into `geo.la`, which declares `Square` and writes
`impl shapes.Shape for Square { … }`, or into `shapes.la`, which declares
`Shape` and writes `impl Shape for geo.Square { … }`.
