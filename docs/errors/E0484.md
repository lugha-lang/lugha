# E0484: A callback takes C's buffer the wrong way

C hands a callback a buffer as a pointer and a count. How the callback
takes it depends on when it runs:

- A `direct` or `realtime` callback runs during C's call, so it reads C's
  memory in place: `View<T>`, or `MutView<T>` to write it.
- A `spawned` callback runs as a task after C's call has returned, when
  C's memory may be gone, so it takes `T[]`, a copy made during the call.

`T[]` in a `direct` or `realtime` callback, `View<T>` in a `spawned` one,
and `Ref<T[]>` in any are this error:

```lugha
extern fun on_block(f: direct fun(f32[], data), user: data); // error: E0484

fun main() {}
```

Take a view, and copy it with `to_array()` only if the callback must keep
the data:

```lugha
extern fun on_block(f: direct fun(View<f32>, data), user: data);

fun main() {}
```

For `Ref<T[]>`, which copied C's buffer in and back out, take
`MutView<T>`: it writes C's memory in place.
