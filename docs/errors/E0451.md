# E0451: A type that doesn't meet a derivable interface

A derivable interface is met through its `derive` blocks: one for a single
type (`i64`, `T[]`), and ones for every tuple, and every struct or enum
that asks with `with I`, whose parts meet the interface in turn. When some
part of a type has no block that covers it, the type doesn't meet the
interface. The message names the path to that part: at the declaration
that asks, or, for a generic type's parameters, where it is used.

```lugha
interface Show {
    fun show(self): string;
}

derive Show for i64 {
    fun show(self): string = "{self}";
}

derive Show for struct {
    fun show(self): string = "a struct";
}

fun show<T: Show>(x: T): string = x.show();

struct Job {
    id: i64,
    run: fun(i64): i64,
} with Show // error: E0451

fun main() {
    let s = show(Job { id: 1, run: fun(x: i64): i64 = x });
}
```

Show only the parts that are data, or add a block for the missing type:

```lugha
interface Show {
    fun show(self): string;
}

derive Show for i64 {
    fun show(self): string = "{self}";
}

derive Show for struct {
    fun show(self): string = "a struct";
}

fun show<T: Show>(x: T): string = x.show();

struct JobInfo {
    id: i64,
} with Show

fun main() {
    println(show(JobInfo { id: 1 }));
}
```

A generic function passes its parameter through by asking for the bound:
`fun twice<T: Show>(x: T): string = show(x) + show(x);`.

Floats meet `Eq` but not `Key` or `Ord`: they have `<`, but `NaN` is
neither below nor above anything, so they have no order of their own.
A struct with a float field can't ask for `Ord`, and float arrays don't
`sort()`. Sort them with IEEE 754's total order instead, or order the
struct by its other fields with an `impl Ord`:

```lugha
fun main() {
    println([2.5, 1.0].sort()); // error: E0451
}
```

```lugha
fun main() {
    println([2.5, -0.0, 1.0].sort_by(f64.total_order));
}
```
