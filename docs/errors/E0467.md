# E0467: A discarded `Result`

A `Result` says whether something worked. Used as a statement, its `Err`
would vanish without anyone looking, so that is an error: handle it, or
drop it on purpose where the code shows it.

```lugha
fun save(text: string): Result<(), string> {
    if text == "" {
        return Err("nothing to save");
    }
    Ok(())
}

fun main() {
    save(""); // error: E0467
}
```

Pass it on with `?`, look at it with `match`, or write `let _ = …;` to drop
it deliberately:

```lugha
fun save(text: string): Result<(), string> {
    if text == "" {
        return Err("nothing to save");
    }
    Ok(())
}

fun main() {
    match save("") {
        Ok(()) => println("saved"),
        Err(e) => println("not saved: {e}"),
    }
    let _ = save("draft");
}
```

A block's last expression is its value, not a statement, so a function
ending in a call that returns a `Result` gives it back. Only `Result` is
checked: an `Option` may still be dropped.
