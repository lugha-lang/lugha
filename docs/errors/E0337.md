# E0337: A struct can't be passed to C by value on Windows yet

An `extern` function may take or give an `extern struct` by value, as C
passes it. Windows x64 passes structs by its own rules, not those of
Linux and macOS, and lughac doesn't lower them yet. Rather than build a
program that would pass the struct the wrong way, a build for Windows
stops at each struct passed by value: an `extern`'s parameter, its
result, or a parameter or result of a callback it takes.

```text
extern struct Point { x: f64, y: f64 }
extern fun length(p: Point): f64;   // error: E0337 (with --target=x86_64-pc-windows-gnu)
```

Pass the struct by address instead, which Windows passes as any C
compiler does:

```text
extern fun length(ptr p: Point): f64;   // C: double length(const struct Point *p)
```

Or build for another target. Scalars, strings, arrays by address and
handles need nothing: they reach C on Windows as they do everywhere.
