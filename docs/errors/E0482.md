# E0482: A `realtime` callback allocates or waits

A callback written `realtime fun(…)` runs during C's call, often on a
thread C keeps for real-time work (audio, sensors, MIDI), where allocating
memory or waiting for anything can stall it. The compiler checks that the
callback, and every Lugha function it calls, does neither: no strings,
arrays, maps, boxes or capturing closures built; no channel operations,
`select`, `join`, sleeping, actor calls, scopes or I/O; no `blocking`
externs; and no calls through a function value or an interface value,
whose code can't be checked. It also can't take a string or an array:
C's call copies them into new Lugha values.

```lugha
extern fun on_note(f: realtime fun(i64, data), user: data);

fun main() {
    on_note(fun(n: i64) { let label = "note {n}"; }); // error: E0482
}
```

Do the work that allocates or waits in a task, and hand it what it needs
through a `Ring`, whose `try_send` never allocates or waits:

```lugha
extern fun on_note(f: realtime fun(i64, data), user: data);

fun main(console: Console) {
    let (notes, incoming) = Ring<i64>.new(256);
    on_note(fun(n: i64) {
        match notes.try_send(n) { .Sent => {}, _ => {} }
    });
}
```

When the callback really needs to allocate or wait, make it `direct`: it
then runs the same way, unchecked.
