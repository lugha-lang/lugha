# E0214: A generic `impl` written with its parameters after the type

A generic block names its type parameters once, right after `impl`, and
then writes the type using them: `impl<T: Num> Grid<T>`. The same block
was once written `impl Grid<T: Num>`, with the parameters after the
type's name. That form couldn't say every block (an array, `impl<T> T[]`,
has no name to put them after), so it is gone: one spelling for one
thing.

```lugha
struct Grid<T> { cells: T[] }

impl Grid<T> { // error: E0214
    fun size(self): i64 = self.cells.len;
}

fun main() {}
```

Write the parameters after `impl`, bounds included, and the type with
them in order:

```lugha
struct Grid<T> { cells: T[] }

impl<T> Grid<T> {
    fun size(self): i64 = self.cells.len;
}

impl<T: Num> Grid<T> {
    fun first(self): T = self.cells[0];
}

fun main(console: Console) {
    let g = Grid { cells: [4, 5] };
    console.println("{g.size()} {g.first()}");
}
```

A block of a struct's or enum's own type names its parameters exactly,
in order: `impl<T> Grid<i64>` is E0214 too.
