# E0508: An argument aliases a `mut self` receiver or a `mut` argument

A `mut self` method may change its receiver while it runs. If one of its
arguments is that same value, or a part of it, the method would be reading
something it is also changing, and the result would depend on the order of
its steps. Lugha rules this out, so a method can always treat its arguments
as unaffected by what it does to `self`.

```lugha
struct Vec2 { x: i64, y: i64 }

impl Vec2 {
    fun add(mut self, other: Vec2) {
        self.x += other.x;
        self.y += other.y;
    }
}

fun main(console: Console) {
    let mut v = Vec2 { x: 1, y: 2 };
    v.add(v); // error: E0508
    console.println(v.x);
}
```

Copy the argument into its own binding first:

```lugha
struct Vec2 { x: i64, y: i64 }

impl Vec2 {
    fun add(mut self, other: Vec2) {
        self.x += other.x;
        self.y += other.y;
    }
}

fun main(console: Console) {
    let mut v = Vec2 { x: 1, y: 2 };
    let w = v;
    v.add(w);
    console.println(v.x);
}
```

A `mut` argument is the same: the function changes that place while it
runs, so no other argument of the call may be that place, a part of it,
or a value of it passed by pointer:

```lugha
struct P { x: i64 }

fun merge(mut into: P, from: P) {
    into.x += from.x;
}

fun main() {
    let mut p = P { x: 1 };
    merge(mut p, p); // error: E0508
}
```

Copy it first, so the function reads a value that doesn't change:

```lugha
struct P { x: i64 }

fun merge(mut into: P, from: P) {
    into.x += from.x;
}

fun main(console: Console) {
    let mut p = P { x: 1 };
    let q = p;
    merge(mut p, q);
    console.println(p.x);
}
```
