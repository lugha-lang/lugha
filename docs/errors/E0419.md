# E0419: Type argument doesn't satisfy its bound

A generic function or type was used with a type that misses one of its
built-in bounds. `T: Num` promises the body it may do arithmetic on `T`s,
`T: Float` that it may call the float operations, and `T: Eq` that it may
use `==`. A type argument has to keep that promise, so a call with one that
can't is rejected where it is written, not deep inside the function.

```lugha
import std.math;

fun main() {
    println(math.sqrt(2)); // error: E0419
}
```

An `i64` isn't `Float`. Other common cases: a `Ref` (or a type holding one)
as a `T: Eq`, and a method of an `impl Grid<T: Num>` block called on a
`Grid<string>`. `Ord` and the other interfaces a type asks for with `with`
are reported as E0451 (a part with no `derive` block, such as a float) or
E0422 (a type that didn't ask).

Pass a type that meets the bound:

```lugha
import std.math;

fun main() {
    println(math.sqrt(2.0));
}
```
