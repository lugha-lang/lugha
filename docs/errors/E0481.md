# E0481: A queued callback takes `Ref<T[]>`

A callback with user data (`data`) and no result is queued: C's call to it
starts a task in the scope that registered it and returns at once. A
callback parameter written `Ref<T[]>` is C's array that the callback may
change, copied back to C when the callback returns. A queued callback
returns to C before it has even run, so its changes could never reach C.

```lugha
extern fun each_block(f: fun(Ref<i64[]>, data), user: data); // error: E0481

fun main() {}
```

Mark the callback `inline`: it then runs during C's call, and C sees what
it wrote once it returns.

```lugha
extern fun each_block(f: fun(Ref<i64[]>, data) inline, user: data);

fun main() {}
```

If the callback only reads the array, take `i64[]` instead: a copy, which
a queued callback may take.
